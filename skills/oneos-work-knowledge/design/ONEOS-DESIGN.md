## 0. 这份文档怎么用

### 0.0 存量界面升级边界（2026-09-10）

本规范决定外观、信息层级与页面排列，**不覆盖各业务现有的数据与行为**。执行前先读 [`UI-MIGRATION-CONTRACT.md`](./UI-MIGRATION-CONTRACT.md)。金额精度、空值、默认值、名录加载方式、临期阈值、附件限制、权限和查询/重置/保存触发条件，由当前业务合同及已验证基线决定。

本页涉及车辆资产到期天数、范例查询后收起等条款，只约束对应范例及已单独确认该行为的页面。迁移现有页面时不得凭视觉规范新增、删除字段或修改事件。公共容器只承载原有控件与内容。

新增 Vue 公共结构见 `vue-kit` 手册；历史 DS-PILOT-01 样板边界见[实现附录](./.spec/implementation-appendix.md)，不代表当前测试部署状态。展示页内的状态和数据不进入正式页面。

### 0.1 地位

- **页面怎么排**：只认 [`ONEOS-PAGE-CANON.md`](./ONEOS-PAGE-CANON.md) + 范例廊。本文不再单独充当「全仓母版说明书」。
- **Token / 硬门禁 / 台账逐块规格 / Ant 对等 / 验收尺**：仍只认本文。
- `DESIGN.md` / `DESIGN-NEXT.md` 仅作历史存档。**不得再作为实现依据**。
- 存量 Rule / Skill 仍按旧章节号引用的，按 **§8 对照表**换算。

### 0.2 一条规则能进本规范的门槛（六条同时满足）

1. **现网做得出**：Ant Token、VXE 配置、CSS 变量或薄封装能实现，不必拷 React DOM。
2. **基准页上有**：本文的数值与手段，在 `oneos-baseline-ledger` 里能量到。
3. **能量一刀验收**：不靠「感觉像」。
4. **先有件再有规**：条款引用的公共类名 / 组件，开发仓与原型仓已有可用实现，且至少一个页面在用。
5. **双引擎对等**：涉及表格的条款须同时说明 Ant 与 VXE 怎么落。
6. **可执行**：有对应审计项或可点自检；查不了的只能是建议，不得标硬门禁。

> 反面教材（旧规范实证）：`.oneos-filter-grid` 定义在主题 CSS、**零页面消费**，五页各写一套私有栅格；
> `--ln-font-mono` 变量与字体都在、**零消费**，车牌日期全是黑体。**光定义不算落地。**

### 0.3 读法

| 列 | 含义 |
|---|---|
| **必须齐** | 验收尺，肉眼可见的效果，差了就是没复原 |
| **允许差** | 源码结构、DOM 层级、图标来源可以不同，**不验** |

历史跨栈（React 原型 → Vue 业务）按“必须齐/允许差”验收；不要求 DOM 同构。
**2026-10-26 同栈增量：本机 Vue 规范示例与 Vue 业务页必须引用同版本范式组件，在相同主题、视口、字体、密度与状态下对标准 UI 区域做 1:1 几何和像素比较。历史跨栈条款不能豁免布局、按钮顺序或组件样式差异。**

### 0.4 技术边界

| 允许 | 禁止 |
|---|---|
| 移植原型 **CSS**（Token / 类名 / 布局）到 Vue 仓 `styles/*-parity.css` | 把 `UIComponents.tsx` / `V2Button.tsx` 等 React **组件源码**拷进 Vue 仓 |
| 用 Ant / Vben 实现**同交互**（Modal、Tabs、Drawer），皮肤跟 Token | 为「像原型」把现网 VXE 改成 `a-table` |
| 薄封装 Ant 控件 | 引第三套组件库（shadcn、Element 新页、再造 `O2*`） |
| 先核对目标测试基线已有 `ConfigProvider` / Token / 全局 CSS，再最小合并缺失的主题与样式 | 把旧本地接线当测试已部署，或重复接入一套主题 |

## 1. Token

**落点**：原型 `src/resources/design-system/oneos-ds-tokens.css`；现网 `oneos-v2-theme.css` + Vben `preferences.theme.colorPrimary`。

### 1.1 品牌色 · 必须跟随偏好（硬门禁）

| Token | 值 | 用途 |
|---|---|---|
| `--ln-primary` / `--oneos-primary` | `#007A55` | 主按钮、链接、选中、focus 环 |
| `--ln-primary-hover` | `#009966` | Hover |
| `--ln-primary-focus` | `#006045` | Active / 强焦点 |
| `--ln-primary-soft` | `#D1FAE5`（暗色 `rgba(0,122,85,.22)`） | Tag 浅底、Pill、菜单选中底 |
| `--ln-on-primary` | `#FFFFFF` | 实心主钮字色 |

`#007A55` 是**出厂默认值**，不是可以写进样式层的字面量。

| 层 | 正确做法 | 禁止 |
|---|---|---|
| 出厂默认 | `preferences.ts` 配 `theme.colorPrimary`（青绿 = `hsl(162 100% 24%)`） | CSS `:root` 写死十六进制当默认 |
| 样式层 | 消费框架色阶 `hsl(var(--primary))` / `--primary-400` / `--primary-700` / `--primary-100` | `--ln-primary: #007a55` 之类字面量 |
| Ant Token | 由 `useAntdDesignTokens()` 传入，不被自定义调色板覆盖 | 自定义 `LIGHT`/`DARK` 里塞 `colorPrimary` |
| 组件内 | `var(--oneos-primary, var(--ln-primary, #007A55))`，字面量只作末端兜底 | 直接写 `#007A55` |
| **浮层 / 面板选中态**（日历日圆、「选中今天」、下拉高亮、区间填充） | 同上 Token；浅底用 `color-mix(in srgb, var(--oneos-primary) …)` | 触发器用 Token、浮层写死 `#007A55` / `rgba(0,122,85,…)`（半截跟随） |

**翻车实况**：
1. 主题层 `:root` 写死主色，覆盖层选择器特异性高于 Ant 动态 token，偏好里换色后被样式层盖回去——**任何主题色都换不动**，不止某一个色。
2. **半截跟随（2026-08-25）**：`V2DatePicker` 触发器边框/图标吃 Token，日历选中日与「选中今天」写死 `#007A55` → 壳层偏好红/紫时浮层仍出厂青绿。

自检：换任一内置偏好色 → 主钮 / 侧栏当前位置 / Pill / 链接 / **日期与下拉浮层选中态** 必须全部跟随。

**禁止**：硬编码旧紫 `#533AFD`、若依蓝 `#409EFF`、Ant 蓝 `#1677FF` / `#3B82F6` 作链接色。

### 1.2 中性色与语义色（层级只有这些，不许再冒新值）

| 语义 | 唯一变量名 | 值 | 禁止写法 |
|---|---|---|---|
| 主文字（标题、强数字） | `--ln-ink` | `#0A2540` | `--ln-text-primary` |
| 次文字（**台账表体主文字**） | `--ln-body` | `#425466` | `--ln-text-secondary` |
| 弱文字（副行、Label、Placeholder） | `--ln-muted` | `#627D98` | `--ln-text-tertiary` |
| 面分隔（表格行线、卡内分区） | `--ln-hairline-weak` | `#EEF2F6` | 手抄 `#EEF2F7` 等差 1 色 |
| 卡片外框 | `--ln-hairline` | `#DCE3EB` | — |
| 控件描边 | `--ln-hairline-strong` | `#C7D2DD` | — |

> `var()` 写错变量名**不会报错**，静默吃 fallback，换主题时不跟随而且肉眼看不出。
> 引用前先确认变量真实存在于 `oneos-ds-tokens.css`。

**表体主文字用 `--ln-body` 而不是 `--ln-ink`**：这是为了让**主色入口**成为整行唯一的高对比焦点。

| 语义色 | 值 | 面积规则 |
|---|---|---|
| 成功 `--ln-success` | `#10B981` | 只做图标 / 徽标 / ≤4px 强调条 / ≤14% 软底 |
| 预警 `--ln-warning` | `#D97706` | 同上 |
| 危险 `--ln-error` | `#EF4444` | 同上 |
| 信息 `--ln-info` | `#3B82F6` | 同上；**不得**用作链接色 |

主色与 `--ln-success` 接近：**主按钮走 primary、成功态走 success，禁止混用**；同屏禁止出现第二套主色。

### 1.3 圆角与间距

| Token | 值 | 谁用 |
|---|---|---|
| `--ln-radius-xs` | `4px` | 到期天数标签等微标 |
| `--ln-radius-sm` | `6px` | — |
| `--ln-radius-control` | **`10px`** | 按钮、输入、Select、筛选入口 |
| `--ln-radius-card` | **`10px`** | 卡片、Modal、Drawer、台账壳 |
| `--ln-radius-pill` | `9999px` | Pill、状态徽标、芯片 |

| 间距 | 值 |
|---|---|
| 页壳水平 gutter（PC） | **24px**（H5 12–16px） |
| KPI 卡内距 | **18px 20px** |
| KPI 卡间 gap | **12px**；KPI 区与台账卡间距 **16px** |
| 台账筛选行内距 | **14px 16px**；芯片行 / 工具行 **10px 16px**；更多筛选展开区 **16px** |
| 更多筛选栅格 gap | **16px 12px** |

**盒模型**：页壳与所有子容器 `box-sizing: border-box`；Flex / Grid 子列 `min-width: 0`。
**禁止** `width:100%` + content-box 让白卡溢出吃掉 gutter。

### 1.4 密度

| Token | 值 | 说明 |
|---|---|---|
| `--ln-control-height` | **36px** | 输入 / Select / 日期 / 筛选入口 / 按钮（H5 ≥44px） |
| 控件字号 | **13px** | 表单与筛选控件 |
| `--ln-control-min-width` | **72px** | 两字按钮下限；图标钮、文字链、表内小号钮不受限 |
| 表单 `labelWidth` | **96px** | 容纳 6 字标签；标签超 6 字请缩写，不要加宽 |
| 表头高 / 字号 / 字重 | **32px / 12px / 600** | 12px 用 500 偏糊 |
| `--ln-table-th-padding-x` | 12px | |
| 表体字号 / 行盒 | **13px / 20px** | |
| 单元格内距 | **8px 12px** | 上下各 8，与 §2.2 行高算式配套 |
| `--ln-table-cell-padding-y-compact` | **4px** | **密集档**唯一受控值，见 §2.2 末段 |
| `--ln-table-row-min-height` | **48px** | **下限**，不是目标值 |

> **按钮不等宽**：高度统一 36 + 宽度有下限 + 超出后按内容自然增长。
> 强行让「导出」和「租赁费用模板」等宽是错的。
> 现网关闭了 Ant `autoInsertSpaceInButton`（默认把「新增」渲染成「新 增」），所以必须补宽度下限。

### 1.5 字体与等宽数字

**正文（A 档 · 系统栈，不自托管中文）**：

```text
--ln-font: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
           "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif
```

汉字允许 Mac 苹方 / Win 雅黑平台差，验收不卡汉字像素。**禁止**把未加载的 Inter / 思源写进正文栈冒充；
**禁止**为此拉 Google Fonts 或 CDN。

**等宽数字（自托管 JetBrains Mono）**：

```text
--ln-font-mono: "JetBrains Mono", "Cascadia Mono", "Cascadia Code", Consolas,
                "SF Mono", SFMono-Regular, Menlo, "Courier New", monospace
```

由 `oneos-ds-tokens.css` `@import` 仓内 `fonts/jetbrains-mono/`（SIL OFL 1.1）。
**栈序硬禁**：JetBrains 必须第一，禁止把 `ui-monospace` 写在它前面。

| 必须走 mono + `tabular-nums` | 保持正文栈 |
|---|---|
| 车牌、VIN / 车架号、单号、合同号、证号、卡号 | 品牌、车型、状态、人名、公司名等中文文案 |
| 金额、里程、天数、日期与时间串 | 说明性文案 |
| KPI 主数字 | KPI 单位后缀（`small`）可用正文栈 |

落地方式：工具类 `.ln-mono`，或 `font-family: var(--ln-font-mono)` + `font-variant-numeric: tabular-nums`。

**同视口不许分裂**（硬门禁）：台账单元格已 mono，同页表单 `input`、车牌类 `V2Select`（传 `mono`）、
日期触发器必须同字族。只修表不修表单是历史翻车根因。
**只开 `tabular-nums` 不够**——字宽齐但字族仍是黑体。`font-family: 'tabular-nums'` 是错的写法（它不是字族）。

**车牌格式**：`浙A88888F`，**禁止**中间加间隔点 `·` 或短横线。

### 1.6 动效与海拔

| Token | 值 | 用途 |
|---|---|---|
| `--ln-motion-fast` | `120ms` | 边框、focus 环 |
| `--ln-motion-mid` | `150–160ms` | 行 hover、菜单选中、次钮 hover |
| `--ln-ease` | `cubic-bezier(0.2, 0, 0, 1)` | 禁 `linear` 机械感 |
| `--ln-elev-1` | `0 1px 2px rgba(10,37,64,.04)` | 贴附，默认不用 |
| `--ln-elev-2` | `0 10px 32px rgba(10,37,64,.10)` | 下拉 / Modal / 日期面板 |

只动**色 / 影 / 透明度**。

**禁止**：Ant `wave` 水波（`ConfigProvider :wave="{ disabled: true }"`）、主钮 `box-shadow` 发光

## 2. 硬门禁（不过 = 未完成）

### 2.1 单元格信息可见性

**门禁一句话：表头写了几项，格子里就得看见几项。**

判据：单元格内每个持有文本的元素，**渲染高度 ≥12px、宽度 ≥8px（随字数放宽），且未被任何祖先
`overflow: hidden` 裁掉**。`overflow: auto|scroll` 滚得到的不算违例；**先被 hidden 切过**再套滚动容器**算**违例。

| 禁止 | 为什么 |
|---|---|
| `td` 内**非单元格容器**（div 等）写 `height` 定值 / `max-height` | 块级盒的 `height` 是定高，内容一涨就被裁 |
| 任何元素（含 `td`）写 `max-height` | 上限即裁切 |
| `line-height: 0` | 连带压掉子元素行盒 |
| `grid-template-rows: 20px 16px` + 外层 `overflow: hidden` | 第一行内容一涨，第二行被挤成 1px 且无报错 |
| 同一元素 `min-height` > `max-height` | 约束自相矛盾，浏览器行为不可预期 |
| 对需要看见的内容用 `sr-only`（`position:absolute; width:1px; clip:rect(0,0,0,0)`） | 按设计就是「留无障碍树、藏视觉」 |
| `display:none` / `opacity:0` 藏正文字段 | — |

**正确做法**：`grid-auto-rows: auto` 或块级堆叠；需要限高用行数上限（`-webkit-line-clamp`，
每行仍 ≥12px），不用像素裁切。行高下限按下表写——**`td` 和普通容器的写法是相反的**：

| 对象 | 下限怎么写 | 实测 |
|---|---|---|
| `td` / `th`（`display: table-cell`） | **`height: var(--ln-table-row-min-height)`** | `height:48` + 单行 = 48；+ 三行内容 = **68**（照常撑开） |
| `td` 内的 `div` 等块级容器 | `min-height`，**禁** `height` | 块级 `height` 是定高，会裁 |

> **`min-height` 对 `table-cell` 无效**（2026-08-19 实测纠正）：`td { min-height: 48px }` 实测行高 28px。
> 本条此前写反，导致 `--ln-table-row-min-height` 在全仓台账上从未生效，10 页主表行高长期 36–47px
> 而无人察觉——基准页的 61px 是内容自己撑的，不是下限撑的。
> CSS 里 `table-cell` 的 `height` 语义**本就是最小高度**，不是定高；当初事故中把内容压成 1px 的真凶是
> `line-height: 0` 与 `max-height`，它们恰好和 `height` 同时出现，条款把无辜项一起判了。

**共享样式优先查** `src/common/v2-migrate-ledger/ledger-row-density.css`——它是多个台账的共同上游，
只改原型自己的 `style.css` 往往压不住。

> **为什么必须自动化**：2026-08-18 实测车辆资产母版，121 个复合格子共 256 行内容，**135 行视觉上不可见**
> （VIN、保险到期日、证照到期日、客户全名全没了）。肉眼评审、无障碍快照、字段清单核对、视觉审计器、
> 静态检查**五种手段全部报绿**——病根是 `sr-only`，DOM 与快照当然正常。**DOM 里有 ≠ 用户看得见。**

**验收（缺一则 Fail）**：

```bash
npx vite --port 5199                                   # 先起 dev server
npm run audit:visibility                               # 全量
npm run audit:visibility -- oneos-baseline-ledger      # 单页
npm run audit:visibility:selftest                      # 尺子自检
```

必须「不可见 0」。违例截图在 `/tmp/oneos-visibility-shots/<id>.png`。

**禁止**用 Grep CSS 关键字、读 DOM 文本、看无障碍快照代替真机审计（这三样当初全放过了）。
**改完 CSS 必须整页导航后再量**：Vite HMR 下 `getComputedStyle` 会读到已删除的旧值。

### 2.2 行高只给算式与下限

**行高 = 内容行数 × 行盒 + 行距 + 上下内距。只给下限，不给上限。**

行盒定义：主行 `line-height: 20px`、副行 `16px`、行距 `2px`、上下内距各 `8px`。

| 行型 | 内容 | 算式 | 下限 |
|---|---|---|---|
| 单行 | 一格一值 | 20 + 16 | **≥48px** |
| 双行 | 主行 + 副行（车牌 + VIN） | 20 + 2 + 16 + 16 | **≥54px** |
| 三行 | 主行 + 2 副行 | 20 + 2 + 16 + 2 + 16 + 16 | **≥72px** |
| 四行及以上 | — | — | **收进详情**，不在台账铺 |

基准页实测行高 **61px**（状态徽标与到期标签把主行撑高到 20 以上），符合算式，**不写死**。

**下限管谁（2026-08-19 补 · 此前缺失导致误判）**：`48px` 只约束**台账主表数据行**。下列不适用，
按各自下限走，**不要为了「达标」把它们撑高**：

| 对象 | 下限 | 实证 |
|---|---|---|
| 台账主表数据行 | **≥48**（密集档同） | 基准页 61 · 车辆资产 65 |
| **嵌套子表行**（合同下挂车辆、账单下挂期次） | **≥28**（= 20 行盒 + 密集档内距 4×2） | 租赁合同 `.lc-contract-vehicle-native-table` 30 · `bfcl-nested` 31 |
| 汇报舱 / BI / 消息中心的紧凑数据条 | 不设台账下限 | 那不是台账，套 48 会毁掉一屏信息量 |
| 弹层内小表、Popover 摘要表 | 不设 | — |

**唯一无差别适用的是可见性判据（§2.1）**：任何一档、任何一种表，每行渲染高度都必须 ≥12px 且未被裁切。

> **下限值必须由算式推出，不能拍**（2026-08-19 自纠）：本表初版给子表定 32，而同一行引用的实证是
> 30 与 31——两个样本全在下限之下，条款一落地就把合规实现判成违例。改按密集档单行算式取 **28**。
> 新增任何下限前先回 §2.2 算一遍：**行数 × 行盒 + 行距 + 内距 ×2**。

> **量到行高偏低时的排查顺序**：先查这页有没有接 Token，再谈密度。
> 实测 79 个有表格的原型中 17 个出现 <48 的行，逐个看下去，真违例的共同点不是「密度调小了」，
> 而是**整页脱管**——`padding` 硬编码在自己的 CSS 里（`.bfcl-table td { padding:14px }`）
> 或写在内联样式里（`<td style={{ padding: '16px 20px' }}>`），从来没读过 `--ln-table-*`。
> **直接调 px 是治标**：下次有人改 Token，这些页照样不动。正确做法是把它接进 Token，再看行高。

**密集档（唯一受控的第二密度）**：视口定高台账（约 10 行/屏）内距取 **4px**，行盒与下限不变，
故同算式得 单行 ≥40 / 双行 ≥46 / 三行 ≈64，其中 40 与 46 会被 `td { height: 48 }` 兜到 48。

| 档 | 内距 | 单行 | 双行 | 三行 | 怎么开 |
|---|---|---|---|---|---|
| 标准（默认） | 8px | ≥48 | ≥54 | ≥72 | 什么都不做 |
| 密集 | 4px | ≥48 | ≥48 | ≈64 | 台账根挂 `.ln-density-compact` 或 `[data-ln-density="compact"]` |

**密度只准靠减内距拿，不准靠裁切拿**——两档的行盒、行高下限、可见性判据完全相同。
**禁止**在页面里私写 `padding: 4px !important`：共享文件 `ledger-row-density.css` 曾同时存在 6px 变量与
4px `!important` 两个值，这正是「三行 64 / 72」两套数字在文档间互相「改回去」的根源。

> **三行到底是 72 还是 64**：两个都对，分属两档。旧 `DESIGN-NEXT.md` §3.1a 的 64 不是笔误，
> 而是当时 `ledger-row-density.css` 里 `padding: 4px !important` 的真实结果，只是没写明它属密集档。
> 标准档内距 8 → 72；密集档内距 4 → 64。**先确认这页是哪一档，再对数字。**

> 写死 `height: 68px` 会同时产生两种走样：内容只有两行也硬撑 68；内容三行被压进 68。
> **被压掉的那种，肉眼与无障碍快照都发现不了。**
> 现网 VXE 68px 与原型 51px 的差，根因不是密度取舍，就是那 135 行被压掉的信息——
> **双侧量到的差值要先查可见性，再谈密度。**

### 2.9 Portal 浮层必须自带主题属性（硬门禁 · 2026-08-27）

```text
展开 · 同体：字段铺满 N 列，操作跟到最后一行右侧（禁 grid-row:1 钉死造成右上空洞）
展开 · 独立区：操作常驻主栅格首行右，但展开块必须 max-height + overflow-y: auto
```

**展开区「空格子」硬闸（2026-08-27）**

`minmax(240px, 1fr)` 的 `1fr` 会把剩余轨道拉宽成等宽空格子：1390 宽铺 5 列 × 262px，
只放 2 个字段就空出 786px，读起来像「这里漏填了三个字段」。**这是筛选区看着空的第一病根。**

| 要 | 不要 |
|---|---|
| 列宽上限封顶（`minmax(240px, 280px)`）+ `justify-content: start`，字段数即视觉宽度 | `minmax(240px, 1fr)` 把空轨道拉成空格子 |
| 字段数按主流断点（1280–1920）**一行装完**取舍；封顶 280 时一行 4 项 | 为凑满一行硬加无业务语义的维度 |
| 宁可右侧留纯画布空白 | 把控件拉到 330+ 宽去填满（筛选值都是短词，拉宽是浪费） |
| 范例可在已确认范围内优化字段安排；存量换行按真实字段布局，不因末行数量删项 | 为追求满格删除原有筛选维度 |

**范例取舍口径**：在已确认的范例范围内收敛低价值维；不据此裁剪存量筛选。例：范例台账有「计划完成日」与「更新日期」两个时间维时，
扫账人关心的是计划与临期，**更新时间不是收敛维** → 砍掉，让一行装完。

**派生维值得占一格**：KPI 写了「其中已逾期 N 单」，展开区就该有「临期状态（已逾期 / 3 天内 / 正常）」，
否则 KPI 点不进明细，钻取链断在第一步。范例见 `LedgerCanon.tsx` 的 `DUE_OPTIONS`。

**已选芯片颗粒度**：芯片按**业务维度**成颗，不按字段成颗。
日期区间是一个维度 → 一颗「计划完成：08-24 ~ 08-31」，移除即整段清；
**禁**用 `Object.keys(filters)` 逐字段生成，那会拆出「起 / 止」两颗，拆一颗留下半截区间。

### 3.5 表格

现网台账事实用 **VXE**，不要为了「像原型」改成 `a-table`。复合单元格用 VXE **slot** 渲染，
把 `.obl-cell` 那套 CSS 搬过去即可：

```vue
<vxe-column field="plate" title="车牌 / 车辆识别代码" :width="210">
  <template #default="{ row }">
    <div class="obl-cell">
      <a class="obl-entry" @click="open(row)">{{ row.plate }}</a>
      <span class="obl-cell__sub obl-mono">{{ row.vin }}</span>
    </div>

```

|---|---|
| 表头 **32 高 / 12px / 600**，浅渐变底 + 主色下边线，`sticky top: 0` | VXE 表头 padding 实现 |
| 表体字号 13、行盒 20、单元格内距 `8px 12px` | — |
| 复合格 `display: grid; grid-auto-rows: auto; gap: 2px` | — |
| 主行 **13/600 `--ln-body`**；副行 **12/500 `--ln-muted`** | — |

| 操作列 `sticky right` + 左侧**软**阴影，横滚时不滚走；**表头须叠写主色 inset 下边线**（见 §3.5.4 右粘硬闸） | VXE `fixed="right"` 亦可 |
| 行 hover 有**可见底色变化** | 具体透明度 |

**右粘阴影硬闸（2026-08-25）**

横滚时操作列 `sticky right` 用左侧 `box-shadow` 做纵深；表头主色下边线也用 `inset box-shadow`。  
**CSS 的 `box-shadow` 不会跨规则合并**——后写的单侧左侧阴影会整段盖掉主色 inset，肉眼就是「操作列左边一道比别的列更深的竖边」，且表头主色线在操作列处断掉。

| 必须 | 禁止 |
|---|---|
| 表体右粘：`box-shadow: var(--ln-sticky-ops-edge)` | 单写硬刀口阴影（如 `-6px 0 14px -6px` 高不透明）当「边框」 |
| 表头右粘：`box-shadow: var(--ln-sticky-ops-th-shadow)`（= edge **+** 主色 inset） | 只写左侧 shadow、指望 thead 通用规则的 inset「还在」 |
| Token 单源：`oneos-ds-tokens.css` 的 `--ln-sticky-ops-*` | 页面私造更深竖边 / `border-left` 冒充右粘分隔 |
| 对照母版：`oneos-hr-process` / `oneos-org-contacts-1` 表头叠写写法 | 窄表无横滚却硬上 Ant `fixed:'right'`（另见右粘边界） |

```css
/* ✅ 表头 */
th.sticky-right {
  box-shadow: var(--ln-sticky-ops-th-shadow);
}
/* ✅ 表体 */
td.sticky-right {
  box-shadow: var(--ln-sticky-ops-edge);
}
/* ❌ 会盖掉主色下边线 */
th.sticky-right {
  box-shadow: -6px 0 14px -6px rgba(10, 37, 64, 0.18);
}
```

#### 3.5.5 数据核验（2026-09-15）

[React 核验台账示范](https://prototype.lnoneos.com/oneos-page-canon/index.html?view=validation) 与 [Vue 对照示范](http://127.0.0.1:5670/?view=validation&revision=1.3) 使用同一组明确样本。迁移按映射复现展示，状态、权限和核验条件仍由业务提供。

| 状态 | 图标 / 色彩 | 文字与弹层 |
|---|---|---|
| 核验正确 | CircleCheck，成功色 | 显示客户或成本的核验依据；不可用绿色掩盖缺少依据 |
| 数据疑似有误 | CircleAlert，错误色 | 结论、差异、当前值及参考值；有原业务权限才提供替换 |
| 待复核 | TriangleAlert，预警色 | 明确待关注原因，不冒称已确认错误 |
| 数据疑似重复 | Copy，预警色 | 关联记录和疑似依据；不自动删除、合并、覆盖或阻断提交 |
| 无法核验 / 待重新核验 | CircleHelp，辅助色 | 说明缺失依据或等待结果；普通缺值为“—”，零值照常展示 |

- 图标 16px、描边 1.75，PC 命中区至少 24px、触屏至少 44px；不叠额外圆圈、阴影或实心底。语义色独立于品牌偏好色；浅色成功/错误/预警分别为 `#007A55 / #B42318 / #9A5B00`，深色为 `#6EE7B7 / #FF8C8C / #FBBF24`，由共同核验色变量提供。
- 悬停、聚焦、点击均能打开。点击不因聚焦重复触发而立即关闭；Escape、关闭钮、点击外部可关闭。键盘可到达说明中的动作，关闭回到触发器。
- 采用 Popover 卡片，宽 320px（最大为视口减 24px）、内距 16px、圆角 10px；标题 13/600、依据 12、字段值 13。使用页面表面色、文字色和浮层层级，深浅色一致；包含按钮时禁止用纯 Tooltip。
- 异常行采用语义色 5% 轻背景、左侧 3px 标识，悬停 8%；可定位字段单独轻底。行内其他文字、来源标签、编辑和更多不整行染红。疑似重复与字段错误可以同时存在，分别保留提示；无来源结果不得自行生成重复状态。
- 已锁定仍可读核验说明；替换、编辑、删除遵循原业务可用条件。示范页手工修改后显示待重新核验，不伪造正确结果。
- React 使用 `V2ValidationIndicator` + `OperationActions`；Vue 使用 `OneosValidationIndicator` + Ant Popover/Dropdown，行状态通过 VXE `row-class-name`。共同皮为 `oneos-ds-validation.css`，组件只消费显式状态和动作回调。
- 材料识别属于分类与待处理呈现，不复用“核验正确/有误”语义：氢气、加油、其他非氢、待识别均以文字分类；仅已明确加油可呈采购待处理提醒。提醒关闭不清事项，处理登记须同时具备承担方、依据和办理凭据。

### 3.6 分页 / 空态 / 载入态 / 错误态

| 元素 | 现网 | 必须齐 |
|---|---|---|
| 分页 | VXE pager 或 `a-pagination` | 总数「共 N 条」；条数文案「N 条/页」全文可见；**禁原生 `<select>`**；条数不可清空；下拉贴底**向上翻**且不被台账 `overflow` 裁切 |
| 空态 | `a-empty` + 自定义描述 | 一句**原因** + 一个**下一步按钮**（放宽条件 / 清空筛选 / 新建）；禁只写「暂无数据」 |
| 载入态 | `a-skeleton` 或 VXE loading | **骨架屏**（shimmer ≤1.2s），不要长时间空白或纯 spinner |
| 失败态 | Toast / 整页异常页 | 文案必须含**下一步**；禁「操作失败，请联系管理员」 |

**空态给动作是硬门禁**，不是可选项——「眼睛知道下一步」靠的就是这一条。

#### 3.6a 空态分两档：找不到 vs 没有了（2026-08-27）

原条款只写了「找不到」那一档，导致被动收件箱（待办 / 待审核 / 消息）空了也被塞「新建任务」类引导——
**用户的活是别人派的，催他自己造一个是错的**。两档判据看这个空是谁造成的：

| 档 | 触发 | 标题 | 动作 | 禁止 |
|---|---|---|---|---|
| **A · 找不到** | 有筛选值 / 搜索词 / 非默认分档 | 没有符合条件的 × | **清空筛选** / 放宽条件（主动作） | 只写「暂无数据」 |
| **B · 没有了**（收件箱清空态） | 无任何筛选，数据源本身为空 | ×× 已清空 | **次级**出路：去看消息 / 查看已办结 / 刷新 | 「新建任务」「去办任务」等催办 CTA；把清空当失败态画 |

B 档三条硬要求：

1. **交代任务怎么来**：一句说清「新任务派给你时会出现在这里，并推送消息」——用户要的是安心，不是催促。
2. **动作降级**：只给 `secondary`，不给 `primary`；办完是好事，不用主色 CTA 抢视线。
3. **图形吃 `currentColor`**：由容器把 `color` 交给 `--oneos-primary`，换偏好色时插画跟着走；
   禁在 SVG 里写死 `#007A55`，也禁用 emoji 当插画。

判定口径：**这个空是用户自己筛出来的，还是系统本来就没派活？** 前者给「改条件」，后者给「安心 + 出路」。
范例：`oneos-page-canon` H5 待办（调试条「待办清空态」可切 B 档）。

#### 3.6b 字段空值与创建信息（2026-09-12 用户确认）

适用于后续 OneOS 原型及本地业务前端的页面改造。字段缺值与整页无数据分别处理；详情展示创建信息时，沿用客户管理页已确认的口径：

| 场景 | 展示 |
|---|---|
| 普通业务字段确实无值 | “—” |
| 详情中的创建人没有记录，或创建时间缺失 | 对应字段显示“未记录” |
| 有创建人编号，但现有人员信息无法匹配姓名 | “姓名暂不可用” |
| 请求尚未完成 | 加载提示，不提前显示“未记录”或“—” |
| 请求失败 | 明确的失败提示及重试入口，不按空值处理 |

创建信息仅供查看，不使用“待补充”引导手工填写，也不推断为“系统创建”或“用户已删除”。已有姓名和时间按原业务值展示；姓名不可用不影响同时展示有效的创建时间。

2026-09-12 日期精度修订：客户列表及详情中的创建时间统一显示为 `YYYY-MM-DD`，后续同类创建信息展示沿用此口径。仅收敛页面展示精度，原始时间、查询边界、排序及导出数据仍沿用业务规则；需要时分秒的其他业务时间按各页已确认要求展示。

本条统一展示文案，不改变数据源、名录加载方式、权限、校验或提交取值。零值、否定值等有效数据不能被当成空值；“不适用”等已有业务含义继续保留。React 原型与 Vue / Ant Design / VXE 页面使用相同状态口径，按各页现有加载和渲染能力实现。

验收随页面改造进行：检查正常值、真实缺失、姓名无法匹配、加载与失败重试，核对普通字段仍按原规则显示；桌面和手机文案完整可见。本次确认为后续统一约定，不代表存量页面已经批量改造。

#### 3.6c 客户合作状态展示（2026-09-12 用户确认）

客户列表采用 6px 圆点加状态文字，无胶囊底色或边框；状态与业务经理保留原双行间距。客户详情采用小型浅底标签，编辑继续使用原下拉选择。列表与详情的状态仅供读取，不使用按钮样式或点击效果。

状态色与主题选中色分离：已合作为绿、洽谈中为蓝、终止合作为红、合约过期为橙，未设置及其他或未知状态为灰。KPI、列表与详情共用语义色；深浅主题仅适配可读性，不改变业务含义。状态文字必须保留，不依赖颜色单独传达信息。本次落地客户页，其余页面随已确认的逐页改造处理。

### 3.7 视觉皮 · B 定稿变量组

A（克制精致）与 B（强表现力）共用同一份 DOM 与布局 CSS，全部差异收敛在自定义属性。
**只落 B 这一组**，A 已归档不实现：

```css
--obl-zebra: #fafbfd;                                   /* 斑马纹 */
--obl-th-bg: linear-gradient(180deg, #f4f7fa, #eef2f7); /* 表头微渐变底 */
--obl-th-shadow: inset 0 -2px 0 rgba(0,122,85,.18);     /* 表头主色下边线 */
--obl-th-color: #35485f;                                /* 表头字色 */
--obl-row-hover: rgba(0,122,85,.075);
--obl-kpi-bg: linear-gradient(160deg, rgba(255,255,255,.96), rgba(248,250,252,.96));
--obl-kpi-accent-w: 3px;                                /* KPI 左侧语义色条 */
--obl-kpi-icon-bg: var(--obl-tone-soft);                /* KPI 图标语义底 */
--obl-pill-active-bg: var(--oneos-primary);             /* 选中 Pill 主色实心 */
--obl-pill-active-color: #fff;
--obl-badge-weight: 600;                                /* 状态徽标 + 同色描边 */
```

全部是 CSS 自定义属性与渐变，Ant / VXE 主题里直接写即可，**不需要写两套模板**。

**这组值推翻了旧规范三条禁令**（禁斑马纹、禁渐变填充、禁用阴影画表头底线），理由见 §9.3：

- **斑马纹**：`#FAFBFD` 与白底差约 1.5% 明度，是宽表横向读行的功能性辅助，不是装饰。
- **微渐变**：表头与 KPI 的渐变明度差 ≤3%，用于把面推远，不是「高大上渐变」。仍禁彩色渐变、玻璃拟态。
- **表头 inset 阴影**：`sticky` 表头用 `border-bottom` 会在滚动时错位或被 `border-collapse` 吞掉，
  `inset box-shadow` 是正确实现，不是 hack。

#### 4.1a 下拉搜索按选项数分档（2026-08-27 · 本尊定）

> 触发：负责人 3 个选项，面板里顶着一个 42px 搜索行（内嵌 28px 带边框灰底 input），
> 与触发器叠成**两层输入框**，搜索区:选项区几乎 1:2。
> 根因是「凡 `searchable` 一律出搜索框」，把可选能力当成了必须件。

**先判维度类型，再看选项数**（本尊 2026-08-27 补：客户名称、项目名称这类必须能打字搜）。
只看当前 `options.length` 会踩一个大坑：**原型 mock 三五条、生产三百条**，
自动判的结果是原型没有搜索框 → 开发照着做 → 现网名录选不动。

| 维度类型 | 判据 | 搜索 | 例 |
|---|---|---|---|
| **名录型** | 数据来自主数据表 / 名录，**随业务增长** | **`searchable="always"`**，不看当前几项 | 客户名称、项目名称、供应商、承运商、人员（负责人 / 对接人 / 经办）、车牌、VIN、站点 / 场地、合同号 |
| **枚举型** | 取值固定，**不随业务增长** | 不传，走下面的选项数阈值 | 状态、结算方式、区域、优先级、临期档、是否 |

名录型即使原型里只有 3 条也出搜索——因为搜索已在触发器内，**面板仍是纯选项、不会回到框中框**（实测负责人 3 项：面板 118px，触发器可打字）。

**选项数阈值（仅枚举型适用）**

| 选项数 | 形态 | 依据 |
|---|---|---|
| **≤ 7** | **不出搜索框**，点开直接列选项 | 7 × 36 = 252px 正好一屏面板，不用滚就全看得见，搜索零价值 |
| **8 – 20** | 搜索**进触发器**（打开即聚焦，打字即筛），面板只放选项 | 视线不跳、省 42px；同现网 `show-search` |
| **> 20** | 同上 + 匹配串高亮 / 分组 | 长名单 |

实现落在 `UIComponents.tsx`：`searchable === 'always'` 强制开，否则看
`SELECT_SEARCH_MIN_OPTIONS = 8`。选项多时不传也自动开（渐进增强，122 个用到 `V2Select` 的文件无需改）。

**交给开发落地的边界**：名录 **> 200 条禁全量下发**。现网走 `a-select` + `filterOption={false}` + `onSearch`
远程模糊查询（防抖 300ms、限 20 条、回显已选项）。原型可用全量 mock 示意，
但 PRD 须标注该维度为远程搜索，否则前端会照原型全量拉。

**H5 Sheet 例外**：Sheet 有独立标题栏与抓手，顶部搜索行不构成框中框，且手机触发器太窄 →
移动端保留面板内搜索行，但**同样过阈值**。

**明确禁止**

```text
❌ 面板内再套一个带边框 / 灰底的 input（框中框）
❌ 选项字号比触发器小一号（13 → 12「点开就退化」）
❌ 触发器 10 / 面板 12 / 搜索框 6 / 选项 8 四种圆角同屏
❌ 面板阴影写 rgba(0,0,0,.18) 纯黑（要吃 --ln-elev-2，随主题走）
❌ 只能鼠标点选：↑↓ / Enter / Esc 必须可用
```

**键盘契约**：`↑↓` 移游标并回卷（越顶到末项、越底回首项）+ 滚动跟随；`Enter` 选中高亮项；
`Esc` 关闭；鼠标 `mousemove` 接管游标（与 Ant 一致）。
注意**事件只在触发器绑一次**——触发器与内部 input 都绑 `onKeyDown` 会因冒泡让 `↓` 一次跳两格（实测踩过）。

### 4.2a 态位矩阵：每个组件要交几个态（2026-08-27 · 本尊定）

> 立项依据：本轮盘点发现**已封装 30 个组件、对等表只收录 12 个**，17 个「代码里有、规范里没写」＝没有约束；
> 且存量组件态位不齐（`V2ImageUpload` 曾无 `invalid` / `loading`，远程搜索的 `V2Select` 无 `loading`）。
> 缺封装的后果已量化：**无输入框封装** → 各页自造 `wf-field` 46 处 / `v2m-field` 40 / `va-field` 25 /
> `v2-fh-input` 17（圆角 8px 与规范 10px 打架）；**无弹窗封装** → 73 个文件各写一套 modal/dialog/drawer。
> 「页面样式不统一」的根因不在页面，在组件缺位。

**态位不搞一刀切**，按组件性质分四档。交付时只验本档要求的态，缺一则未完成。

| 档 | 组件 | 必交态位 |
|---|---|---|
| **录入类** | `V2Input`（含 amount/password/search 分档）· `V2Textarea` · `V2ImageUpload` | **七态**：正常 · 悬浮 · 聚焦 · 禁用 · 只读 · 错误 · 加载 |
| **选择类** | `V2Select` · `V2Cascader` · 日期时间 6 件 · `V2RadioGroup` · `V2CheckboxGroup` · `V2Switch` | 正常（未选 / 已选）· 展开 · 禁用 · 错误 · 加载；多选另验**溢出成颗**；级联另验**父级可选 + 多选混选** |
| **展示类** | `V2Badge` · `V2Tag` · `V2Steps` · `V2Timeline` · `V2ApprovalProgress` | 各语义档齐（默认 / 进行 / 成功 / 预警 / 失败）+ **深浅双色**；无禁用与加载 |
| **反馈与结构类** | `V2Button` · `V2Modal` / `Drawer` / `Popconfirm` · `V2Empty` · `V2Toast` · `V2Pagination` · 分段器 / Pill / 筛选件 | 按钮验**变体全谱 + 悬浮 + 禁用 + 加载 + 三尺寸**；分页验首页 / 中间 / 单页 / 整体禁用；空态验**两档**（§3.6a）；弹窗验脚部按钮档位 |
| **数据陈列类** | `V2Table` · `V2Descriptions` | 表格验**标准档 · 密集档 · 横滚右粘 · 空态 · 加载**五态，且复合格每行 ≥12px 不被裁（§2.1）；描述表验无框 / 带框 / 纵向 / **空值占位** |

**态位语义硬口径**

| 态 | 视觉 | 禁止 |
|---|---|---|
| 悬浮 | 只加深描边，**不动底色** | 与聚焦同款高亮（分不清哪个生效） |
| 聚焦 | 主色边 + 3px 光环，`color-mix` 跟随偏好 | 写死 `rgba(0,122,85,…)`；只改边不给环 |
| 禁用 | 灰底 + 灰字 + `not-allowed` | 只降透明度导致文字读不清 |
| 只读 | 保留控件外形 + **虚线边** | 用 `readOnly` 输入框冒充详情展示（§5.4b 纯展示走描述表） |
| 错误 | 语义红边 + 红光环 + **错误行一句** | 只红边不给原因；红字堆政策长段 |
| 加载 | 锁交互 + 转圈 / 走条，**触发器上就要看得见** | 只在面板里出加载（不点开看不出）；远程检索时显示「暂无选项」误导 |

**组件廊（事实源）**：`src/prototypes/oneos-v2/` 默认视图 = `ComponentCanon`，
四类组件按实际卡片与状态目录展示，可切深浅双色；数量以组件廊当前渲染结果为准，不在多个文档手写副本。**改组件必须同轮把新态补进廊**。

**为何非要封装表格**（2026-08-27 补）：手写 `<table>` 让规范里最容易做错的四条各页各犯一遍——
① 行高下限写成 `min-height`（`table-cell` 上**无效**，Token 形同虚设）；
② 复合格写死 `grid-template-rows` + `overflow:hidden`，压出「紧凑」但信息看不见；
③ 横滚时操作列滚走，或表头只写左侧阴影**盖掉**主色下边线、左缘出现一道深竖边；
④ 私写 `padding: 4px !important` 自成一档密度，改 Token 时纹丝不动。
`V2Table` 把这四条一次做对，列的 `render` 仍完全交业务，不限制字段与排版。

**两个存档 Showcase 已于 2026-08-28 删除**：`DesignSystemShowcase` /
`StandardBusinessDesignShowcase` 及其配套 `L0CheckSection` / `L1CheckSection` /
`ShellThemeDemoSection` 与那份 150KB 的 `UIComponents.tsx` **副本**（合计 442KB）整体拔除。
它们各带一份组件库副本、与 design-system 单源打架，是长期被禁抄的真正原因；
同时也是全仓最后 103 处旧紫的所在地。降级为「存档、禁抄」不管用——只要文件在，
下一个人（或分身）照样会打开来抄。历史结论查 git 历史即可。

### 4.2b 图片查看与跨部位相册（2026-09-23）

图片缩略图点击后打开预览，下载单独提供；查看和下载分别遵循原业务条件。详情、附件区及上传后的有效图片共用查看能力。预览不修改原记录、上传值或删除条件。

- **照片组**：同车同次交车或同次还车包含所有部位照片；从任意部位进入，能连续翻到其他部位。部位是标签；交车、还车分组，不混其他车辆或记录。使用页面提供本组完整可见集合和稳定顺序，不只传点击部位的图片。
- **定位**：优先打开点击图片，显示“部位 · 全册序号/总数”，缩略图可直接跳转。首尾禁用对应翻页，单张隐藏翻页。
- **查看**：初始完整适配，缩放 1–4 倍、放大后拖动、复位；切图重新适配居中。左右键翻页、Esc 关闭；焦点进入浮层并在关闭后回到触发器。
- **状态**：加载中有反馈，坏图可重试且不阻断其他图；无图显示“暂无图片”。无下载权隐藏下载入口；下载失败提供反馈与重试。上传中、上传失败继续由原上传控件处理。
- **对等交付**：React 用 `V2ImageViewer`；Vue 3 用 `OneosImageViewer`。普通 `FileUpload`、`ImageUpload` 及业务查看区保留各自数据、回显和权限，再接入共同查看行为。不得直接替换上传绑定值或业务下载方法。

冻结业务与验收见 [图片查看合同](./.spec/image-viewer-product-contract.md)，接入见 [实现附录](./.spec/image-viewer-implementation.md)。本轮提供规范组件和示范；存量入口需逐页接入和回归，不能据此宣称全站已统一。

## 5. 台账之外的页面型式

### 5.1 视图选型（按需，禁机械三视角）

列表 / 看板 / 主从是**能力菜单**，不是「凡台账必须三块都上」。

| 视角 | 何时上 | 常见否决 |
|---|---|---|
| **列表** | 扫账、对账、多字段对比、筛选后进详情 | —（台账底盘，通常必有） |
| **看板** | 列 = 真实业务阶段，且存在拖动推进语义 | 列只是筛选项别名；卡片塞不下决策字段 |
| **主从** | 高频连续办多单，右栏能完成**主要**办理 | 主要办理在重详情 / 表单全页，主从只会变半成品分屏 |

PRD 必须写「视图决策」：做了哪些、**明确不做哪些 + 理由**。未上的视角**不要**在顶栏留空的分段器占位。
审计时若「缺看板 / 主从」，先读 PRD 视图决策；有合理理由**不算违规**。

基准页示范口径：

> 只做列表 + 二期详情。不做看板（车辆运营状态是资产属性，不是可推进的流程阶段）；
> 不做主从（调拨、证照续办、维修派工都在各自业务页完成，右栏放不下也不该放）。

### 5.1a 主子台账（展开行）

2026-09-12 补充[租赁合同与车辆规范样板](http://127.0.0.1:5670/?view=nested&revision=1.3)，效果待产品经理评审。主表一行一份合同，展开区紧贴该行显示所属车辆；这是台账展开行，不是列表右侧办理的主从视图，也不替代单份合同编辑表单。

- 子区独立表头、所属单据标识及操作列，使用浅底、缩进建立从属关系；最多两层。PC 可横向滚动，手机转换为主卡片内的子卡片。
- 合同统计与车辆明细计数明确区分单位；子筛选、子分页不改变主统计。每份合同各自保留筛选和页码，局部重试不影响其他合同。
- 双行子表标准档至少 54px（20 + 2 + 16 + 8×2），紧凑档至少 48px；§2.2 的 28px 仅适用于单行子表。不得裁掉副行，金额和里程的表头、数值同向右对齐。
- 子表分页并标明“本合同…辆”，不用内部竖向滚动堆叠；空、错、加载在所属展开区分别呈现。
- 主表身份点击进入合同详情，子表身份点击进入车辆详情；返回恢复原浏览上下文。动作只在其所属层级出现。

完整规则见 [`ONEOS-PAGE-CANON.md` §3d](./ONEOS-PAGE-CANON.md) 与[样板合同](./.spec/nested-lease-review-1.3.md)。此评审增量不改变任何真实合同状态、审批和结算规则。

### 5.2 侧栏与二次页

**一个原型 = 侧栏一项**。详情 / 编辑 / 新增在**同页用状态机**做满完整 UI，不拆 `#page=` 套娃。

「同页模拟」解决的是侧栏套娃，**不是「可以不做内页」**：PRD 须有「二次页清单」；
交付必点通「列表 → 详情 → 返回」「详情 → 编辑 → 返回」。**禁止用 Toast 冒充详情页。**

### 5.3 详情 / 表单页头

**2026-09-12 辅助行修订：** 查看、编辑页标题下不再重复展示客户名称、单号等辅助信息，也不保留该行空白。返回按钮、分隔线和单行标题垂直居中；正文中既有的名称、编码字段及状态摘要继续按原规则显示。

```text
[← 返回列表] │ 页面标题（20px / 800）                         [原有操作；短表单主 CTA]
```

| 返回用描边 / 次按钮，文案「返回列表 / 返回台账」 | — |

### 5.4 表单页双布局（生成前必须声明 `layout`）

| 方案 | 骨架 | 适用 |
|---|---|---|
| **A · 侧栏工作台** | PC `grid: 1fr + 340px`，右栏放指派 / SLA / 审批进度 | 单单据深度填报且**需要**右栏业务 |
| **B · 横向整屏（B1）** | **无**右栏；主区 `width: 100%` + PC 水平边距 **20–24px** | 宽字段矩阵、多列录入、合同条款等密度页 |

选型规则：有右栏业务 → 必须 A；无右栏且需横向空间 → 必须 B；**同一页禁止混用**；B **不得**做成贴边 0 padding。

#### 5.4a 表单栅格铁律（2026-08-27 · 范例廊反向固化）

> 触发：范例廊表单用 `repeat(auto-fill, minmax(240px, 1fr))`，1440 宽铺出 **6 列**，
> 6 个字段挤成一行、输入框拉成长条，页面剩一大片灰底。业务页照抄就是「一两行 + 满屏空白」。
> 现网对等：Ant `a-row :gutter` + `a-col`，24 栅格。

| 项 | 必须 | 禁止 |
|---|---|---|
| **列数封顶** | 一行**最多 3 列**（`a-col span 8`）。≥1600 宽也是 3 列，多出来的宽度留白，不加列。增量由 `gate:design` 规则 `form-grid-cols` 拦 | `auto-fill` / `auto-fit` 无上限；1440 以上铺 4–6 列 |
| **断点** | ≥1280 → 3 列 · 768–1279 → 2 列（span 12）· ≤767 → 1 列（span 24） | 写死 `md:grid-cols-2` 一档；PC 与 H5 同一套列数 |
| **跨列** | 长文本 / 地址 / 备注 / 上传 / 富文本 → 整行（span 24）；两倍宽字段 → span 16 | 长文本挤在 1/3 列里换行成小方块 |
| **测量宽度** | 表单内容区 `max-width` **1240px**（有右栏档 1440），页内居中 | 内容跟随视口无限拉宽，2560 屏上 input 长过一尺 |
| **分区节奏** | 字段 >6 个拆 2–3 张分区卡（基本 / 业务 / 补充），卡间 gap 16 | 一张巨卡塞 15 个字段 |
| **卡内间距** | 行距 18 · 列距 20；`align-items: start`；label 12/600 顶置、行高 18 | 字段高低不齐、label 撑出台阶 |
| **只读态** | 走 §5.4b 描述表，不要拿输入框壳装只读文字 | `readonly` 输入框冒充详情 |

**2026-09-12 客户独立页宽度修订（已确认）**：区分外层工作区与字段正文。客户详情、编辑的页头、纵向滚动容器、编辑操作条铺满工作区，PC 水平边距 24px；仅字段正文保持最大 1240px 并居中。滚动条沿工作区右边缘展示，不跟随正文收窄；手机延续单列及 12px 水平边距。宽表、车辆子表按所处页面的已确认布局使用横向空间，不套用客户字段正文的限宽。该修订先落到本地客户独立页，其他页面逐页接入。

**2026-09-13 详情宽度修订**：1.3 规范样板的页头、滚动区域、操作条与外边距统一使用工作区宽度；资料详情的字段正文居中且最大 1240px，租赁合同等含车辆、费用明细的业务详情字段与履历正文使用工作区全宽。此条覆盖 2026-09-12 将合同详情正文一律限宽的旧说法，见 [`ONEOS-PAGE-CANON.md`](./ONEOS-PAGE-CANON.md) §0。

**同日台账同步**：租赁合同主子台账原型与本地租赁合同列表的 KPI、筛选、操作区、表格和分页均使用工作区可用宽度，电脑左右 24px、手机左右 12px，各区左右对齐。台账不复用详情正文的阅读限宽；超宽字段在表格内横向滚动，不使整页溢出。

```css
@media (max-width: 767px) { .form-grid, .form-grid.is-2 { --cols: 1; } .field.is-span-2 { grid-column: auto; } }
```

**跨列不许把末行跑空（2026-08-27 · 范例廊二次固化）**

> 触发：给「事项」加 `span 2` 建立宽度节奏，本区 6 字段变 7 格，3 列排下来末行只剩「办理日期」一个，
> 右侧空两格——本想治朴素，结果比一刀切三等分更空。

| 项 | 必须 | 禁止 |
|---|---|---|
| **格数对齐** | 跨列后本区**格数须为列数整倍**（3 列档 → 6 / 9 格）。凑不齐就减字段或改回等宽，不留末行落单 | 末行 1 格 + 右侧 2 空格；为凑整倍硬加无用字段 |
| **跨列依据** | 由**内容长度**决定：事项 / 标题 / 地址跨 2；备注 / 上传整行。短值（车牌、日期、电话、金额）一律 1 格 | 为「好看」给短字段跨列；整卡等宽后再抱怨朴素 |
| **派生值不占格** | 由其他字段带出且不可编辑的值（客户带出的区域、车牌带出的车型），落在来源字段的 `hint` 行，不单独占一格 | 派生值做成可编辑 `V2Select` 冒充待填项，既占格又制造错填 |
| **等宽是对的场合** | 一区字段全为短值（金额 / 结算 / 日期 / 站点 / 对接人 / 电话）→ 3 等分 2 行满格即最优，不必强造节奏 | 每张卡都硬塞一个跨列字段 |

**卡头右侧写分区摘要**

分区卡头右侧是**信息位不是装饰位**。有增量信息就写：本区已填数（`5 / 5 已填`）、关键值
（`¥12800.00 · 月结`）、字数（`27 字`）、张数（`2 / 6 张`）、截止时刻、流程步数（`第 2 / 3 步`）。
卡头空着是「朴素无奇」的实测主因之一——但**增量为零就留空**：卡内两个字段已把负责人和计划日
写明的「指派」卡，再抄一遍到卡头只是噪声。判据是「摘要能不能让人不展开卡就知道情况」，
不是「每张卡都得挂点东西」。

**必填未填要在字段上看得见**

吸底摘要（`还有 1 项必填未完成：事项`）只是**汇总**，不能替代字段级反馈：未填必填项须给
`is-invalid` 红描边 + `aria-invalid` + 字段下一句短提示（`请填写事项`），并与卡头已填数、提交禁用联动。
只有吸底一句 = 反馈缺位（体验规范 §1 反馈一等公民）。

#### 5.4b 只读详情用描述表（对等 `a-descriptions :column="3" bordered`）

**2026-09-13 已确认修订**：客户和租赁合同的普通只读字段统一为**标签在上、内容在下、浅色边框分格**的描述表。标签 12px / 行高 18px，值 13px / 行高 1.65，间距 6px；单元格内边距 14px 16px、圆角 6px。分区标题 14px / 600、内边距 16px 22px，正文内边距 22px，分区间距 20px；手机分区内边距 16px。该修订替代旧的“108px 标签列＋值列”横排要求，避免客户和合同各写一套普通字段样式。

资料详情保持 1240px 阅读宽度；含车辆、费用明细表的租赁合同详情采用全宽业务变体。页头与滚动容器仍铺满工作区、PC 外边距 24px、手机 12px。此处替代 §5.4a 旧同步说明中对所有合同详情正文一律限宽的部分，客户资料正文限宽继续有效。核心合同条款及车辆费用默认展开，客户等辅助资料可折叠，分区导航负责展开并定位。

合同状态和审批状态分别使用小型浅底标签，颜色独立于主题选中色；原有字典文案、取值和操作限制不变。创建人和创建时间放在正文底部同行展示、手机分行；创建日期精确到天，缺失、姓名不可用、加载及失败重试执行 §3.6b。

| 项 | 必须 | 禁止 |
|---|---|---|
| 列数 | ≥1280 三列 · 768–1279 两列 · ≤767 一列；长字段整行，按信息组安排顺序 | 键值对用 `auto-fill` 铺成 6 列 |
| 长字段 | 情况描述 / 处理意见单独整行 | 塞进 1/3 列截断 |
| 数字 | 金额 / 车牌 / 电话 / 日期 `--ln-font-mono` + tabular | 混字族 |
| 短单据 | 概要描述表之外再给一张**处理记录**（`V2Timeline`） | 只有一张 3 行卡片 + 满屏空白 |
| 编辑页里的只读上下文 | 处置 / 审核等编辑页顶部的「这单是谁的」照样走描述表 | 图省事复制表单栅格再挂 `readOnly`，灰底输入框排一片 |

**右栏卡不许只有两行字（2026-08-27）**

侧栏档右栏承载指派 / 时限 / 进度。**时限卡必须有时间量的视觉**：剩余时长 + 已耗时进度条
（`已耗时 / 总时限`，≥75% 转预警色）+ 超时处理 + 卡头截止时刻。只写「剩余 18 小时 / 升级主管」
两行 = 该密的地方没密。同理左栏若明显短于右栏，先查是否漏了业务卡（处置填报缺现场凭证
`V2ImageUpload` 是实测高频漏项），不要靠拉高间距填空。

#### 5.4c 吸底操作条（长表单档）

| 表单档 | 主 CTA 放哪 | 说明 |
|---|---|---|
| **短表单**（不滚动，≤2 分区） | 页头右侧（§5.3） | 保持扁平页头形态 |
| **长表单**（要滚动 / ≥3 分区） | **吸底操作条**：主题卡面 + 顶发丝线，右侧按钮，左侧现有校验摘要 | Vben `Page` footer 插槽 / `a-affix` / sticky 为可选实现，按页面容器选择；React 用 `V2Button`，Vue 用现有 `a-button` 对等变体，保留事件、权限与校验 |

硬要求：

- 以可见性验收：最后一个字段、错误提示与主 CTA 均可完整看到和操作，滚动到底不被操作条遮挡。
- 滚动区与底栏是分离区域时无需重复预留底栏高度；覆盖式底栏才按实际覆盖高度预留安全区。`flex` 取值按现有布局选择，不以某一个声明值代替可见性验收。
- 同一页**不要**页头与吸底条各放一套主 CTA。
- 校验摘要写「还有 N 项必填未完成：事项、客户」，不写「请正确填写表单」。

**同卡 / 同栅格内控件必须同高同圆角**：PC 一律 `height` 与 `min-height` 同为 36、圆角 10、字号 13
（H5 44 / 14）。**禁止** PC 写 `height: 36` 却留 `min-height: 44`（日期区间最易翻车）。

表单校验失败时同时给三层反馈：控件红边 + 字段下红字、顶部 Toast 摘要（「还有 N 项必填未填」）、
滚动锚点到第一个出错字段。

**待办收件箱口径（2026-08-27 · 本尊定）**

定义：**用户进来就能看到自己要做什么**。据此三条：

1. **已办结不进列表**。办完的单去「我的」看统计与归档，不占找活干的视线。
2. **分档按动作类型，不按单据状态**。用户问的是「我要办什么」（待处置 / 待审核），
   不是「这单到哪一步」。状态降级为脚行色点文字。
3. **概览与列表同源**。顶部「待你处理 N 件 · 逾期 M」必须按**当前筛选结果**算；
   拿全量算逾期会和眼前 2 条记录当面打架。

**卡片色彩额度（反堆砌）**：一张列表卡最多两处彩色胶囊——**类型**（我要办/我要审）与**临期**（逾期/N 天内）。
状态、金额、单号一律走字阶与字族区分。三个以上胶囊同屏即视觉噪音。

**底部导航与吸底条不共存（2026-08-27）**

App 级 `V2MobileBottomNav` 与页级 `V2MobileActionBar` 同屏 = 底部两条条、真机误触。定版取舍：

| 原吸底动作 | 去处 |
|---|---|
| 筛选 / 搜索（页级视图控制） | 顶栏 `rightActions` 图标位（`iconOnly`，有筛选值时挂 `badge`） |
| 办理 / 处置（单据级动作） | **点列表卡进详情**再办；主 tab 页不放全局 CTA（办谁的单说不清） |
| 新建（高频录入） | 顶栏图标位，或列表区右下悬浮钮 |

带底部导航的页仍可用 Bottom Sheet：Sheet 遮罩须盖住底栏（`z-index` 高于 `nav`）且不飞出壳。

**毛玻璃底色 Token（2026-08-27 · 补缺）**

`V2MobileHeader` / `V2MobileBottomNav` 的 `backdropBlur` 读 `--ln-surface-card-translucent`，
该变量此前**全仓从未定义**，组件只能回落到写死的 `rgba(255,255,255,0.92)`——浅色下巧合正确，
暗色下整条顶栏与底栏漂成白块。已在 `oneos-ds-tokens.css` 补浅色 `rgba(255,255,255,.92)` /
暗色 `rgba(18,20,24,.92)`。遇到「组件暗色不跟」先查变量是否存在，别在业务页覆盖背景打补丁。

**刘海安全区（2026-08-27 · 壳级修）**

`.v2-h5-notch` 是 `absolute top:0 / z-index:99`，会压住业务顶栏。实测 `oneos-v2-h5-approval`、
`oneos-v2-h5-inspection`、`oneos-v2-h5-delivery`、`oneos-v2-h5-map`、`oneos-v2-h5-task-create`
与范例廊 H5 的标题**全部**被吃掉 28px——属**壳级缺陷**，逐页打补丁必漏。
已在 `h5-shell/h5-shell.css` 用 `:has(> .v2-h5-notch)` 统一给 `.v2-h5-body` 让出 `padding-top: 28px`，
并在壳顶补一条 `--ln-surface-card` 底色让刘海嵌进去（真机观感）。
**业务页不要再自己加顶部 padding**；改壳后须回归至少 5 个 H5 母版，确认标题不被压且内容未被挤出壳外。

**H5 判定信号**（防 PC 误切）：仅 `window.innerWidth ≤ 767` 或显式 `data-viewport="h5"` 才切 H5 形态。
容器宽度 ≤767（如主从 340 侧栏）**不算**。

**触控档位**：H5 里的 `V2Button` 必须传 `size="lg"`（44px）。默认 `md` 是 PC 的 36px，
实测吸底「筛选 / 办理」与「加载更多」三处都曾低于 44 而无人察觉。

**自检**：必须在 375 / 390 手机框里真点「筛选 / 加载更多 / 吸底」。
源码有 `{/* Bottom Sheet */}` 注释不算验收通过。

### 5.6 原型调试条出展示区

2026-10-26本批Vue六页：普通业务URL无调试工具；独立预览显式`?debug=1`才显示业务组件之外的「验收工具」Ant按钮与默认关闭抽屉，复用框架偏好，不遮挡业务与分页。该条覆盖本批历史浮球/原生chip外观，其他旧原型按下文执行。

视口切换、主题切换、方案 A/B 切换等**非客户功能**控件，必须放在手机壳 / 业务画布**外侧**（兄弟或更外层），
带 `PROTO DEBUG · 非产品 UI` 文案或 `data-prototype-debug="true"`。
**禁止**叠在壳顶、业务页头、台账画布内——研发与交付 AI 会当成产品功能照抄。

### 5.7 公网访问口令门

发布到对象存储的业务页必须有口令门（口令 `lingniu`，`sessionStorage` 记住本会话）：

- 判定单源 `src/common/oss-access-gate.ts`：**本机 Make / localhost 免口令**，仅公网 OSS 宿主弹门。
- 未通过口令**不可见业务正文**（整页 Gate，不是只挡按钮）。
- 标注壳 `PrototypeAnnotationHost` 挂在 Gate **之外**，保证未输口令时公网仍能取到 PRD / 目录。
- robots + noindex 与口令门**叠加**，不可互相顶替。

## 6. 文案与指引

### 6.1 禁标题墙与说明书墙

| 位置 | 要 | 不要 |
|---|---|---|
| 台账 / 列表 / 看板首屏 | 直接从 KPI / Pill / 筛选 / 主操作起笔 | 模块 h1 + 标题下灰字描述；白底描边「说明卡片」 |
| 详情 / 表单页头 | §5.3 结构 | 页名下再挂描述行 |
| 区块 / 弹窗标题 | 保留功能标题 | 标题下堆政策长段、角色百科、联调备注 |
| 卡片单选 | `description` 最多一句后果 | 副文案塞匹配算法 / 政策墙 |

**禁止内部词进 UI**：原型演示、视图决策、Stripe、Agent、Make、分身、另排期。

### 6.2 词典

本节的“审批 → 审核”仅适用于已有明确改名确认的业务模块。本轮 PC 界面统一保留现有流程名称、状态、意见和权限；没有该模块的改名确认，不因样板文案替换“审批”，也不自动添加双名称。

| 用户可见文案 | 写 | 不写 |
|---|---|---|
| 已明确确认改名的审核动作 | 按该模块确认的词典使用审核 / 待审核 / 审核中 / 审核通过 / 驳回 | 同一已确认流程混用新旧名称 |
| 存量业务与技术标识 | 原流程名称、代码标识符 `approvalStatus`、API、枚举、路由 path 保持不变；确需在交付材料对照名称时说明映射 | 仅因视觉统一全局替换流程名称 |

### 6.3 空态、失败与报错

1. **空态**：一句原因 + 一个下一步动作。
2. **失败**：文案必须含下一步，禁「操作失败，请联系管理员」。
3. **只给人话**：主视觉区禁止出现堆栈、`Exception`、`at com.`、SQL、类名、字段英文名、错误码字面量、`traceId` 原文。
   `code` / `traceId` 只能通过次要入口「复制给支持」交给研发，默认折叠。
4. **前端唯一出口**：拦截器只把净化后的 `message` 交给展示层；疑似技术串一律替换为统一人话。
5. **去重**：同一 `traceId` 短时间不重复弹 Toast；Toast 同时最多 1 条。

### 6.4 指引强烈 = 结构上只留一条明路

| 条款 | 规则 | 违例 |
|---|---|---|
| 唯一主钮 | 同一操作区只有 1 个 primary | 三个实心钮并排 |
| 主次重量 | 实心 vs 描边一眼分得出 | 次钮透明无边，看不出可点 |
| 空态 / 失败 | 必须给下一步 | 只写「暂无数据」 |
| 当前位置 | 侧栏选中 = 3px 主色条 + 主色软底 + 600 字重，三件套齐 | 只换字色 |
| focus 环 | 2px 主色 + offset，**永不移除** | `outline: none` |
| 行 hover | 表格行 hover 有可见底色变化 | hover 无反应 |
| 不靠颜色单传 | 状态 = 颜色 **+** 文字（必要时加图标） | 只靠红绿区分 |
| 主色白名单 | 主 CTA、选中态（含 Pill 实心）、链接、focus 环、当前位置条、KPI ≤4px 语义条 | 其余位置上主色 |

### 7.4 还原交付的三道闸（现网复刻时）

**闸 1 · 读得到才动手**：原型源码（`index.tsx` + 组件 + CSS）、真实长度 mock 数据、

把多页模块压成一个「简化演示页」；交「业务理解草图」时宣称是「原型还原版」。

**闸 2 · 两张单**：按 §0.3「必须齐 / 允许差」逐条勾，缺一则未完成。

**闸 3 · 缺口回问，不自改设计**：

| 情况 | 必须做 | 禁止 |

**数据必须真实长度**：VIN 17 位、公司全名十几字、至少一页 10 行同时渲染、含空值与超长与已过期边界。
三条短样例撑不破布局，所有裁切与折行问题都会等到开发接手才暴露。

### 9.5 存量接管清单（2026-08-19 实测 · 取代「33 个原型刷 B 皮」）

**定性更正**：这不是皮肤问题，是**接管**问题。多数存量页从未读过 `--ln-table-*`，
`padding` 硬编码在自己 CSS 或内联样式里。**先接 Token，再谈 B 皮**——顺序反了就是白干：

#### A 类 · 主表行高低于 48（10 页 / 79 个有表格页）

**注意**：下表是**审计器分层之前**的人工判定记录，保留作为背景。审计器现已按 §2.2 分层
（主表 / 子表 / 豁免），直接跑 `npm run audit:visibility` 看「行高偏低」清单即可，不必再逐页肉眼分辨。

**已于 2026-08-19 接管完毕，全仓 0 违例。** 记录根因与改法备查。

**根因不是像素，是一条写反的 CSS**：下限一直写成 `td { min-height: 48px }`，而 `min-height` 对
`table-cell` **无效**（实测行高落到 28px）。也就是说 `--ln-table-row-min-height` 在全仓台账上从未生效，
这 10 页长期 36–47px 而没有任何一道闸报错。改成 `td { height: ... }` 后（table-cell 的 `height`
语义即最小高度），共享层一处改动直接修好 4 页。
