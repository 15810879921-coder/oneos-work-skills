# OneOS 页面设计与验收约束

修订：2026-10-27-r1。来源：租赁合同设计复盘及用户“按你的建议来做约束”的确认。

## 1. 适用范围与执行方式

适用于后续 OneOS 列表、详情、表单及其弹层的新建、改版和本次改动涉及的关联路径。存量随迭代检查，不自动批量改造。本文件规定设计过程与可检查的结果，不定义新的业务规则、尺寸 Token、组件 API 或发版权限。

- **必须先识别设计基底**：按项目 `AGENTS.md` 判断 OneOS 1.0 / PC 1.3 或已确认的 OneOS 2.0；采用对应版本的规范和同技术栈范例。2.0 的既定视觉与组件不被本次租赁合同参考覆盖。
- **规则各司其职**：业务字段、权限、计算和生效认当前产品合同/主规格；页面结构认项目现行页型规范；颜色、尺寸与组件认现行设计系统；本文件约束准备、自检与证据。文字、范例和已确认决策冲突时，记录具体冲突，仅暂停依赖该冲突的部分，不静默择一。
- **必须留下检查结果**：使用 [页面设计评审记录模板](./templates/page-design-review.md)，或在现有 `.spec` / 评审报告中记录等价内容。允许引用已有有效记录，禁止机械重复六套文档。
- **按变更范围检查**：新页面覆盖全部适用项；局部修订只检查受影响项与直接关联路径，记录其余项不适用或复用依据。已确认局部修改直接执行，不新增重复确认。
- **结论四态**：通过 / 失败 / 未验证 / 不适用。通过须有证据；不适用须有理由。必要项失败或未验证时，不得称该范围设计验收完成。环境不足可以继续无依赖的工作。
- 这是项目工作指令及人工可执行的检查约束。本次未新增原生 Hook、CI 或发布阻断器，不宣称全员工具已加载、存量已合规或今后不会再出现问题。

## 2. 六份最小检查清单

### A. 页面基线（开始前）

**PD-01｜同一版、同一入口。** 记录实际页面 URL、路由/对象/场景、源码目录及提交号或内容指纹、当前业务依据、规范版本、真实宿主、用户实际视口与外观配置。端口相同不证明同版本；说明本地模拟、正式服务和固定交付包各自范围。不得用第二套自造外壳代替目标宿主的验证。

**PD-02｜现行范例与来源。** 列表、详情、创建/编辑、弹层分别映射到现行页型/组件范例；只复用适用结构。模板、规范正文、可运行范例有冲突时先纠正本轮直接使用的入口，保留历史记录。不能只写“遵循规范”，也不能默认拼装所有视图、KPI 或批量操作。

### B. 任务与字段（设计前）

**PD-03｜先盘点真实任务。** 明确谁使用、最高频查看对象、主要办理动作及完成结果；对照现行页面、字段/操作清单和已确认规格。每项操作记录“角色 → 输入及附件 → 校验 → 是否审批 → 生效时点 → 结果 → 应保留的旧事实”。入口能打开不等于办理完整，提示成功不等于真实业务已完成。

**PD-04｜字段生命周期。** 字段须有业务来源、产生阶段、可见/可编辑角色、默认、必填/格式、联动及保存行为。区分签约约定、实际执行、历史快照及当前档案；不在早期表单要求后续环节才产生的信息。沿用现行下拉与模板来源，不编造“标准版/专项版”等业务选项；没有正式来源的演示候选须标清。

**PD-05｜指标、状态与空值。** 指标明确对象、累计/当前、去重、查询范围及单位，数量可追到相同口径的明细。不同事实的状态分开表达，申请、审批、上传、归档和生效不得互代。普通缺值继续按现行空值规则显示“—”；有明确业务含义时才显示“未上传 / 不适用 / 未到阶段”等。创建信息缺失、加载中、加载失败分别处理，不推断为系统创建。未知金额不得填 0；有效的 0 和否定值不得隐藏。复合单元格可省略无信息的副行，但不得隐藏必要业务状态或用空白冒充已完成。

### C. 信息优先级（排版前）

**PD-06｜首屏与默认内容。** 标明首屏必须可见的对象身份、关键状态、核心数据和主要动作；默认页签由最高频任务决定。统计说明放简短帮助提示，桌面支持悬浮/键盘聚焦，触屏有可用入口。逐项检查 KPI、页头、间距与重复标题占用，不能通过裁切内容、固定小行高换取紧凑。首屏目标按实际容器与页型记录，不为所有页面强定相同行数。

**PD-07｜操作区和筛选区。** 查询动作、页面/单据级动作、记录级动作分工明确。查询控件与查询/重置按钮按同一控制行对齐；有高级条件时必须能找到“更多筛选”。多个业务操作按频率和权限分组，主要动作可见，低频动作进入有名称的分组菜单，危险项独立分组。全局操作不在正文重复堆放，局部记录操作留在对应区域。刷新为表格工具，不抢主操作层级；按钮左右位置按已选页型执行，不一律套租赁合同。

**PD-08｜列表必查项。** 主键与关键字段可辨认，按任务选组合列；品牌/型号等是否拆列由业务决定。宽表操作列固定右侧，无多余空白，横滚后菜单可达；长表头不挤坏排序和工具。核对列设置适用性及入口、分页总数/页码/每页条数、空错载和搜索重置行为；固定业务表不需要列设置须说明理由。多选与批量操作必须有业务依据，不能为套模板新增。

**PD-09｜详情与内容层级。** 返回、身份/编号、状态及统一操作区紧凑组织；可复制的业务编号提供明确反馈。优先采用整体容器和内部区域组织，独立卡片须有任务依据。高频附件与关键记录入口就近可达，不能埋入多层页签。主导航与模块内分类视觉层级可区分；同级导航保持稳定对齐/选中范围，窄屏仍可操作，不用裁切文字制造等宽。各明细视图呈现本类型关键事实，不把同一套字段机械复制到所有视图，不重复堆叠相同信息。

**PD-10｜表单与办理选择。** 多段、需完整核对的任务采用表单页；短任务按既定页型采用弹层或直接保存。创建、编辑、续办能复用已确认字段，但不得带入不应复制的唯一编号、历史附件或实际执行信息。分段导航、必填、联动、复制配置、保存草稿和提交/核对路径必须可用；固定操作栏不得挡住最后字段或错误提示。费用模板按其真实业务机制展示，不能擅自把模板明细变成再次勾选的商品。

### D. 状态与动作（实现前）

**PD-11｜完整状态。** 覆盖正常、空、加载、失败/重试、权限不足、禁用及原因、长内容等适用状态。控件的悬浮、聚焦、选中、错误必须可区分；正确输入后重验并解除对应错误，关联字段变化后清理不再适用的错误，不等下一次整页提交。保留键盘焦点和可访问名称，不以删除所有焦点样式处理双描边。

**PD-12｜审批与历史。** 涉及审批时，设计申请中、通过、驳回、撤回、失败和生效的适用路径；有效值与待审批值分开，提交不能提前覆盖已生效合同。会改变签订后事实的操作须留变更记录：事件、摘要、操作人、时间、结果及关联单据，必要时展开前后值、原因和附件。系统事件标来源，缺失操作人按“未记录”处理。人员转交明确对象层级和影响范围，不改写历史操作人。

**PD-13｜风险与未决项。** 计费、补计、交接、权限等规则未确认时列清依赖范围和待决问题，不按视觉偏好猜测。演示可展现输入与公式，不能把待定口径计算成已确认金额。涉及历史事实、主体变更、审批生效、金额转换时，按现有风险规则做必要独立复核；普通文案/样式不因此扩大流程。

### E. 交互与宿主适配（自检时）

**PD-14｜配置同源。** OneOS 1.0 页面须能嵌入实际 RuoYi/Vben 宿主，主题色、字号、圆角和深浅模式来自宿主；其他基底使用其已确认适配方式。覆盖正文、按钮文字、标签、页签、表格、分页、浮层及弹窗，禁止只让触发器变色而面板写死。按钮使用适配背景的前景色，业务状态色保留语义，不把所有状态染成主题色。样式限定作用域，不能用通用 `label` / `input` 等规则破坏组件内部结构。字段标签保持稳定，可操作区域用适度背景/箭头/状态值反馈；不把标签一起加链接下划线。对象名称等真正链接仍遵守其既定规则。

**PD-15｜真实尺寸与关键路径。** 至少记录实际用户视口和适用的宽/窄布局；响应式改动检查涉及断点两侧。回读实际可用尺寸，不把设定值当实测。新页/外观改动覆盖默认与非默认主题、字号/圆角可配置端点、深浅模式，并补一组大字号+窄容器组合；未支持配置记不适用，未测试记未验证。核对长名称、横滚、固定列/页头/页脚、浮层边界及最后一行可达。实际从菜单/入口走列表→详情→返回、表单纠错→核对/保存及相关记录跳转；按本轮范围取适用路径。

**PD-16｜有预期结果的样例。** 按业务状态准备合成数据，至少覆盖主要正常、异常、缺值和长文本；涉及车辆/计费/审批时增加相应边界反例。记录每组预期指标、明细与操作结果，不为好看编随机数。不能用 Mock 证明正式接口、真实权限、审批、计费或文件存储已接通；本地暂存与上传成功分开呈现。

### F. 同版依据（交付时）

**PD-17｜证据对应。** 交付记录实际入口、版本/指纹、视口/外观配置、主要状态截图与交互结果，人工对照确认首屏容量、层级、对齐、工具栏、表体和分页。静态检查、构建、逻辑测试、视觉、接口及部署分别给结论；HTTP 200、截图存在、组件名命中或零报错不能替代页面验收。复用证据须说明输入未变；规则、实现或环境变化后，仅失效并重做受影响部分。

**PD-18｜连续变更与同版交接。** 每轮记录新增/替代决定、未受影响内容、影响页面和失效证据，当前入口指向唯一有效版本。业务规则保留在产品合同/主规格，技术映射放实现附录，交接只作摘要与索引；源码、规则、示例、已验证/未验证能力同版交付。保留历史固定包，不用新页面覆盖旧版本记录；交付成功、对方理解、正式集成和上线分别确认。

## 3. 不得泛化的租赁合同选择

以下只作为租赁合同的已确认实例，其他模块必须重新判断适用性：车辆履约作为默认页签、合同不做多选批量、签约阶段不录车牌/VIN、换车一组一条、客户级业管转交与合同级业务员交接、无忧包价格及追溯补计、维保计费、续签与终止审批。

可复用的是任务分析、整体层级、统一操作区、清晰统计口径、配置同源、状态完整和同版证据；不得复制业务规则或演示数据当正式实现。已纳入本项目规范的业务组合参考可使用，不能从任意邻近业务页复制私有样式。

## 4. 收口判据

交付前由执行者逐项回答并给对应证据：

1. 第一屏能找到关键数据和下一步吗？
2. 同一动作在列表、详情和弹层中的含义、权限、结果一致吗？
3. 数字、状态、空值和候选选项都有依据吗？
4. 当前宿主换主题、字号、圆角和宽度后仍可读、可操作吗？
5. 开发能从示例与规则判断正常、异常、审批中及生效后的结果吗？

任何一项不能回答时列明缺口及影响，不把检查责任留给用户逐处找问题；待确认仅聚焦真正改变业务/设计的决定。未受影响工作继续推进。
