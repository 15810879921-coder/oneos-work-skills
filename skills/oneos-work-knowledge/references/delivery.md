# 交付：到测试分支为止

## 需求与方案
把目标整理为当前范围、非目标、角色、状态/字段、正常与异常路径、验收 ID。优先读取双库适用规则，记录来源/状态/固定提交；实现现状核目标源码，历史索引不能代替。规则缺口先调查；不可裁决的业务差异交用户，不凭现有 UI 推导正确行为。

小优化用简短验收卡，较大/跨模块变更再补方案、接口/数据变化和风险。按需调用本包 [specialists.md](specialists.md) 的架构、指标、体验方法。仅影响界面才读设计；原型、PRD 都按必要程度制作，不要求每项先画原型。若项目约定要求正式产品/技术意见，核其真实来源和适用范围；不新增逐步确认。

## 开发前与实现
读取目标仓 AGENTS、依赖/构建配置及适用规范；开发库要求的五类工程资产仍必须完整读取并核 manifest SHA。检索节流不豁免必读项。检查工作树，不覆盖别人改动；选择隔离工作区；代码获取/推送遵守运行平台要求。现有项目模块、接口、权限、数据字典要核真实版本。

实施同时维护必要测试。验证覆盖实际改动与依赖，不机械全量也不能只查静态语法。页面自检需真实渲染；设计静态检查不代替截图、交互与业务结果。变更会影响共享接口、字典、权限、任务、报表或另一端时列出影响和回归。

## 合入与停点
1. 核目标测试分支、保护条件和写入触发器。自动部署或未知触发行为不满足“等待统一部署”。保留工作分支/MR并报告阻塞，不改流水线或抢部署。
2. 检查源/目标实际差异，防止夹带其他需求；处理冲突后重新运行受影响检查。目标已有其他变更，不能把自己自测当作整分支通过。
3. 在授权内合入，保留源分支，不强推或自动删远端分支；读回目标包含本次内容的证据。
4. 交接 templates/handoff.md：AC、提交、检查、页面入口、角色/数据、依赖、关联回归、已知缺口。SQL只准备版本化脚本、兼容性和执行说明，本包不直接修改共享 TEST/PROD 库；依赖包发布按项目实际授权和交付规则处理，不默认为已发布。
5. 状态记 `awaiting_test_deploy`。`check_packet.py branch` 仅检查声明字段，不代表已合并。平台状态映射见 [lifecycle.md](lifecycle.md)。测试任务可准备，测试结果仍为未执行。

返修使用原验收点和缺陷证据。非紧急新增范围另留来源，不偷偷扩大当前承诺。修复进入测试分支后再次等部署；“代码已修”不能提前关闭缺陷。
