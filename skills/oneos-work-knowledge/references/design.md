# 体验规范仍是设计标准的一号位

本包随带 `design/` 中当前正式来源的派生快照，packageId 为 oneos-design-system-20261027-current（PC1.3 / Runtime1.0.6）。文件哈希及来源范围见 design/manifest.json。它来自有未提交增量的已交付工作区快照，不冒充纯 Git 或最新云端版；不携带旧 Skill 人设和本机运行依赖。规范原文提及的外部 Skill、工作流和作者路径仅为上游历史上下文，不成为本包运行依赖；只采用适用的设计条款。

## 阅读顺序与适用
先读 design/INDEX.md 的按任务路由；页面类型/布局读 ONEOS-PAGE-CANON.md，尺寸/Token/组件读 ONEOS-DESIGN.md 相应完整章节，页面行为读 PAGE-DESIGN-CONSTRAINTS.md。Vue/Ant/VXE 读 VUE-ANT-MAPPING.md 与对应同栈示例，迁移才读 UI-MIGRATION-CONTRACT.md。入口不强制每次全文读140KB规范，但必须覆盖本次所有适用条款及例外。

项目已配置并核实的新规范版本或用户明确指定版本优先，记录替代关系；没有新正式来源时使用随包固定快照。云端迁移尚未执行，不声称设计正本已经在双库。未来迁移到开发库设计目录须一并维护 manifest、索引和原规范入口，旧包作为历史快照。不能用邻近旧页或记忆覆盖正式规范。

## 三个接点
1. 交付前：记录任务主目标、页面类型、同栈组件、适用规则/规范版本、宽窄/主题/状态覆盖及例外。
2. 实施中：复用项目已有与规范一致的组件与 Token，检查空/错/载/权、滚动、弹层、表格/表单、反馈、键盘可达与可读性。范例的 Mock、合同业务限制和宿主专属代码不复制成真实业务。
3. 验证中：确定性样式/属性/几何检查＋实际截图/交互；Midscene辅助观察，不凭审美猜标准。静态匹配类名不是视觉验收。

业务规则定行为，体验规范定表达，工程约束定实现；三者真实冲突只暂停相关决定并提出可比较方案，不私自削弱规则。

## 维护与例外
独立体验入口可制定/更新规范、评审页面；新标准保留来源和生效版本，不能为让失败通过自动降标准。例外记录 ruleId、原因、范围、决定来源、失效/复核条件；仅在实际授权范围内更改云端正式规范。它不自动拥有业务改码、独立QA或发版权限。

交付输出 templates/design-review.md：适用/不适用依据、标准组件、验证方法、证据、未决项。纯后端具体说明不涉及界面即可，不强制读设计全集。
