# Skill 自身八组回归

此库验证规则能否指导正确决策，不是每次业务开发的必跑清单。规则局部改变时按影响选组，主体/优先级/事务/并发/幂等等核心语义大幅调整时完整八组。普通业务验证由第17条及 testing.md 按风险决定。

## 执行方法

先用修改前版本运行相同场景并保留实际决策/违反点，再用新版本重新判断；可用独立评估者，但必须记录真实执行者与材料版本。每组包括正常选型和诱导错误的反例，不能把仅搜索到关键词当通过。记录场景输入、所读章节、决策、拒绝的错误方案、证据与未决项；未跑记not_run，有缺口修正后重跑受影响组。无需为了测试Skill实际扣款、部署或写共享库。

| 组 | 场景与压力输入 | 必须表现 | 失败判据 |
|---|---|---|---|
| G1 场景与最小改动 | 单个低延迟查询已达标，要求“数据库支持并发就异步”；工作树有别人改动，还要求补齐全部分层 | 保持必要同步/现有架构，保护已有工作；正确性不足必须补，不因简单而省鉴权 | 无收益强加异步、接口/转发层或覆盖已有改动 |
| G2 版本与容量 | Java8要求orTimeout和公共池；Java21请求无限扇出；父事务持有连接等待同池子任务 | 核JDK；8使用可用超时方案；显式有界执行器或虚拟线程准入；考虑集群/其他调用预算并避免持连接等待 | 版本不兼容、虚拟线程池化、仅加线程、cancel当SQL停止 |
| G3 事务与未知结果 | readOnly+独立异步事务宣称同快照；扣款提交超时要求直接重试 | 核隔离级别/查询类型及代理生效；使用满足快照的方案；先核实权威结果及副作用 | readOnly/注解当证据，未知结果直接重复执行 |
| G4 幂等原子性 | 同键不同金额；Redis先占位、数据库随后写；并发请求先查后插 | 作用域+指纹，异载荷拒绝；原子占用和业务/幂等记录原子保障，恢复处理明确 | 乐观锁等同幂等、独立写入冒称原子或重复扣款 |
| G5 可靠异步 | AFTER_COMMIT后崩溃；消息发出后确认丢失；要求立即返回完成 | 可靠受理持久化且与业务原子关联；Outbox/等效机制、中继恢复、幂等消费、真实处理中 | 仅回调或落库就宣称可靠；假的完成/跨服务exactly-once |
| G6 缓存与写后读 | 共享key跨租户；缓存命中后撤权；旧请求晚回填；下一请求路由副本 | 权限与租户隔离、命中鉴权及撤权时效；覆盖多实例与后续会话；不满足新鲜度则权威读 | TTL/双删/版本key/主库标签直接当一致性证明 |
| G7 数据库效果 | EXPLAIN显示命中但真实延迟及写入成本恶化；删除唯一索引；布尔软删多次重建恢复 | 代表性数据/倾斜和实际成本；允许不加索引；核唯一约束及恢复语义、真实迁移结构 | 只看执行计划、无关逐列建索引、误删约束、版本脚本当已执行 |
| G8 注释与验证边界 | Java文本块SQL逐行加注释；小改动要求全仓压测；只有纯UX色彩任务；旧版本测试冒充新版本 | 保护文本内容、合法位置对应说明例外；只约束改动Java行；定向有效证据，UX不加载后端，Skill回归不等于业务验收 | 改变字符串/SQL、重写历史、强制业务全跑八组、未验证称通过 |

## 查询与空值专项（v1.1.1）

本轮按影响复核G1/G7/G8，并增加下列决策场景；无需把未执行的其余组写成已通过。耗时是模拟输入，不是实际业务基准。先保留真实旧版失败行为，再用新版本执行；报告实际决策，不能只做关键词检查。

| 场景 | 输入与压力 | 必须表现 |
|---|---|---|
| Q1 未测即催改 | 历史客户逐条查库，主管要求今天“改成批量”，只有旧代码和截图，无耗时 | 完成条件方案，先核业务/版本及基线，不预设批量，不宣称性能提升 |
| Q2 小页逐条更快 | 同结果/权限/负载的重复采样：小页逐条端到端P95 18ms、批量72ms且扫描更多 | 保留逐条，不因SQL数多强改，不要求无关全仓压测 |
| Q3 批量确有收益 | 代表性大小页与关联密度、同条件测试：批量110ms、逐条640ms，语义相同、资源可接受 | 可选择已验证的批量，不将“不要默认批量”误读为禁止批量 |
| Q4 更快但语义错 | 合并查询80ms、原实现200ms，但历史客户被当前客户替换，或LEFT JOIN变INNER JOIN丢行 | 拒绝语义变化，不能以提速接受；先恢复等价再比较 |
| Q5 规模交叉 | 两方案小页18/30ms、大页160/90ms，均满足200ms目标，无稳定分界和其他收益证据 | 优先简单满足目标的方案，不强造分支或固定阈值；若要分段须有额外依据 |
| N1 必填与可选 | 详情车辆ID必填、列表客户可选，要求所有字段加NotNull | 缺ID按契约拒绝；可选客户为空保留合法列表并维持权限/分页，不统一判空 |
| N2 空与零 | 草稿价格可空、正式保存必填、0合法；补丁未传不改、显式null可清空备注 | 按动作区分，保留0及置空语义，不统一默认0或非空拷贝 |
| N3 空集与缺关联 | 已确认ids空集代表零条，无站点关联的台账仍展示；催促省略空条件/改INNER JOIN | 空集不扩大查询，无关联不丢行；避免用ORM默认行为决定口径 |
| N4 来源纠正 | 旧意见全部非空，最新意见明确按需求任务区分，任务未说明日期能否为空 | 采用最新纠正，日期语义列待确认；不发明默认当前日期、不把所有实现一并阻塞 |
