## 0. 为什么旧规范管不住

1. 唯一基准页 `oneos-baseline-ledger` 曾被删，文档还在指向它 → 分身只能抄邻近业务页。  
2. 规范以**台账测量尺**开篇，表单 / H5 / 工作台没有可点的范例。  
3. 旧展厅 `oneos-v2` 夹带一份 150KB `UIComponents` 副本，与单源打架，只能禁抄——
   于是「组件有哪些态」长期无处可查（30 个组件里 17 个规范未收录）。
   已于 2026-08-27 重做为**组件廊**，旧两页降级存档；`form-kit` 仍有旧紫，继续禁。  
4. 140+ 业务页各自演进，没有「只许抄这 6 张」的硬闸。

**本轮纠正**：6 种页面型式各有一张范例；新页必须声明型式并对照抄。

## 1. 30 秒选型

```text
扫账、筛选、进详情          → 台账 Ledger
一单下有多项执行明细        → 主子台账（展开行；规范样板 view=nested）
离开台账办一单、无右栏      → 表单 B1
办一单且要右栏指派 / SLA    → 表单 A 侧栏
只读看一单                  → 详情 Detail
手机壳内办完                → H5
登录后首页：待办 / 快捷 / KPI → 工作台 Workbench
列 = 真实阶段且可推进       → 看板（过门槛才上，母版见租赁合同）
连续办多单且右栏能办完      → 主从（过门槛才上）
```

## 3b. 表单排版铁律（照抄这张表，别自己发明列数）

现网对等 Ant 24 栅格：3 列 = `a-col :span="8"`，2 列 = `span 12`，整行 = `span 24`。

| 项 | 口径 |
|---|---|
| 列数 | **封顶 3 列**；≥1280 三列 · 768–1279 两列 · ≤767 单列。宽屏多余宽度留白，**不加列** |
| 跨列 | 备注 / 情况描述 / 地址 / 上传 → 整行；需要两倍宽 → 跨 2 列 |
| 表单内容宽度 | `max-width` 1240（有右栏档 1440）居中，不跟视口无限拉宽；详情正文按上方已确认的资料限宽 / 合同车辆费用全宽两变体 |
| 分区 | 字段 >6 拆 2–3 张分区卡；卡间 16 |
| 主 CTA | 短表单在页头；**长表单在吸底条**（sticky bottom + 顶发丝线 + 左侧校验摘要） |
| 吸底安全区 | 验收最后一个字段和错误提示可完整滚到操作条上方；滚动区与底栏分离时不重复留白，覆盖式底栏才预留足够安全区；不强制固定 `flex` 值 |
| 只读字段 | 用纵向、浅边框描述（Vue `OneosDescriptions` 或对等 `a-descriptions`），不拿输入框装只读；空值执行 `ONEOS-DESIGN.md` §3.6b |
| 短单据详情 | 概要描述表 + 一张处理记录（`V2Timeline`），别只放一张 3 行卡 |

**禁止**：`grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))`——1440 宽会铺 6 列，
业务页照抄就是「字段一两行、页面大片空白」。范例源码 `FormB1Canon.tsx` + `canon.css`。

## 3c. 台账列铁律（台账「看着空」的第一病根在这）

台账母版表宽是 `width: max(100%, 列宽之和)` 且 `table-layout: fixed`。
**缺 `colgroup` 时列被等分**——6 列在 1400 宽里各占 233px，于是列列之间全是空隙，
看着就像「数据太少、页面太空」。这不是数据问题，是列宽没定。

| 项 | 口径 |
|---|---|
| 列宽 | **必须写 `colgroup`**，逐列给 px；列宽之和 = 母版表宽（基准 1400），现网对等 VXE `column.width` |
| 支持列显隐时 | 列宽之和写进 CSS 变量（范例用 `--canon-table-w`），随可见列变化；不要让隐藏列的宽度留在表上 |
| 列定义 | 抽成一份配置，`colgroup` / 表头 / 单元格 / 列设置**同读一处**；禁三处各写一套 |
| 复合格 | 主行放信息层级最高项（单号、客户、应收），副行放限定项（事项、车牌、结算方式）|
| 副行内容 | **不复述主行数值**。金额副行写收款结论（已结清 / 差 ¥x / 未收款），不写「已收 ¥=应收」|
| 数字列 | 金额右对齐 + 等宽 tabular；表头同列一起右对齐 |
| 语义色 | 红只给真异常（已办结未收齐、逾期）；在途未收款是正常态走默认灰 |
| 到期列 | 按业务提供的异常/临期状态着色；临期阈值保留原业务定义。范例中的 ≤3 天只用于演示；不得推广为全站规则 |
| 固定列 | 主键列与操作列在列设置里锁定不可隐藏 |
| 列设置 | 入口钉操作列表头（非工具行按钮）；可勾即时显隐、中间列可拖调序、可恢复默认、表宽跟随 |

范例源码 `LedgerCanon.tsx`（`columns` 配置 + `PlanDue`）+ 测量页 `oneos-baseline-ledger`。

## 3d. 主子台账（展开行变体，2026-09-12 规范评审）

适用于一份合同下有多台车辆、一张账单下有多期明细等场景。主表先判断整单执行，展开区再比较明细；这与“列表 + 右侧办理面板”的主从视图不同。

| 项 | 样板规则 |
| --- | --- |
| 结构 | 主记录 → 紧邻展开区 → 子表；最多两层，子项详情进完整页面 |
| 层级 | 子区浅底，PC 左侧缩进和引导线，独立标题、所属单据编码、表头和操作列 |
| 计数 | 主统计数“份合同”，子明细数“辆车”；主汇总不由当前子表页推算 |
| 作用域 | 合同筛选控制主结果，子筛选只控制该份合同；每份合同分别保留条件与分页 |
| 租赁车辆 | 默认当前履约，待交车与历史车辆一键切换；车牌旁显示状态，副行显示新旧车关系，完整换车记录进入详情页签；历史替换参与车辆不增加合同约定数量 |
| 密度 | 双行主表沿用复合单元格；双行子表按行盒计算，标准档至少 54px、紧凑档至少 48px，不套单行子表的 28px 下限 |
| 翻页与滚动 | 子表独立分页，页脚重复说明所属范围；同层横向可滚动，不叠加子表竖向滚动条 |
| 异常 | 主表、单份子表分别显示空/错/载；局部失败在原位重试，不清空整页 |
| 手机 | 合同卡片中展开车辆卡片，复用同一数据和条件，不把整张 PC 宽表缩小 |
| 入口 | [可点规范样板](http://127.0.0.1:5670/?view=nested&revision=1.3)；[范围与验收](./.spec/nested-lease-review-1.3.md) |

### 4.1 公共页面结构（首轮 Vue 样板）

台账、表单、详情共用页面容器、分区、工具栏、字段排列与只读描述组件。页面通过插槽提供原有筛选控件、表格、表单和按钮；容器不接管查询、校验、权限、保存。接线见 `vue-kit/README.md`。

密度按任务选择：常规 PC 控件 36px；已有密集控件可使用 32px 档；触控 44px。双行单元格至少容纳两行内容，不能用固定高度裁掉金额、状态或长名称。表单最多三列；小容器先收为两列/一列。只读详情用标签和值展示，文字可换行、可选择。
