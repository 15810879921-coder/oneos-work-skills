# 状态台账 1.0.2

唯一源：本目录。新增组件显式选入，不替换旧消费者。基础查询→展开条件→底线分类和右侧业务操作→表格→分页。查询/重置/展开词汇及位置由组件拥有。

`OneosStatusLedger` props：`id` 必填；`expanded`（v-model）、`filterCount`、`tabs` (`key,label,count,title,disabled`)、`activeKey`、`tabsLabel`、`querying`、`queryDisabled`。事件：`query`、`reset`、`update:expanded`、`update:activeKey`。

插槽：`primary` 基本条件（直接 label+隐藏名称+原Ant控件）；`advanced` 展开条件（直接 label+span字段名+原Ant控件）；`actions` 右侧业务按钮，次操作在前、创建主操作最后；`queryNotice` 查询未生效提示；`secondary` 可选业务排序/说明；默认表格/数据状态；`footer` 原记录数与标准分页。没有状态时使用`title`。

模块保留所有字段、选项、事件、权限和接口；不以`osl-*`私有CSS改写布局，不套回旧的查询/Tab/操作容器。表格内容不复制到示例来冒充比较基准。规范示例按冻结字段配置引用同一组件。

六份具名字段配置为 customer、lease、replacement、pickup、billing、return。无高级字段时不提供 `advanced` 插槽（billing），不能为了共用检查虚构筛选。有分类用底线Tab，无分类用标题，无业务动作不造按钮。组件只拥有查询和操作骨架，精密台账、合同主子表与月度三视图的业务内容各自保留。

整页高度由宿主和表格共同承接：本批1440×1000默认收起态，分页须在初始首屏完整可见且真实命中，数据充足时至少显示8条完整64px主记录。Schema 4在任何裁图或scrollIntoView之前留存视口、分页坐标、真实命中和文档及祖先的零滚动证据，禁止先滚动再声称首屏可达。窄屏或展开态可自然滚动至分页。自检须计算实际可见完整行数，不能用DOM记录数代替。顶部像素通过只覆盖标明区域，整页布局或交互失败时仍不能交付。

跨工作树分发仅复制此目录并生成SHA256清单；源和副本任一字节不同均阻断设计通过。UI源码与预览调试工具分目录交付。组件新增文件不影响未选入消费者。

## 标准分页（OneosLedgerPagination）

页脚有无左侧汇总，分页均靠内容区右边缘；不得依赖空占位节点或模块 CSS 推到右侧。共享组件负责对齐，Schema 3 检查实际页与规范页的右边距为 0，并验证移动 1px 必须失败。记录数与可用条数档位按业务保留，不用相同示例数字伪装整页像素一致。

`OneosLedgerPagination` props：`current`（当前页）、`pageSize`（每页条数）、`total`（总记录数）、`pageSizeOptions`（可选，默认 `[10, 20, 30, 50, 100]`，按原消费者配置传入）、`disabled`（可选，默认 `false`）。事件：`change(page, pageSize)`，页码或每页条数变化时发出。组件统一显示总数、页码、每页条数选择器；页码和选择器高度为 32px，当前页为浅底描边。用于台账 `footer`，不要再包一层 VXE pager 或另写局部分页皮肤。
范式表格主记录行固定为 64px；此约束仅适用于本范式表格，不改变其他台账或表格的密度规则。

1.0.1：数字型带清除按钮输入框的内部 input 显式保留 tabular-nums，避免宿主重置样式顺序造成差异；只作用于已接入状态台账的筛选控件。
查询区使用独立绘制层，避免真实宿主与规范示例采用不同合成路径造成控件边缘差异；不改变控件布局、边框、事件或业务数据。仍须同时核验原始像素、非抗锯齿差异、几何和重要绘制属性，不能以此忽略真实差异。

1.0.2：查询区与操作区统一创建绘制边界，消除宿主内容层对描边和图标边缘栅格化的影响。宽屏诊断原始差异99像素、非抗锯齿差异4像素；统一操作区绘制边界后原始23像素、非抗锯齿0像素。正式结论仍以完整矩阵为准，不能用诊断替代验收。
