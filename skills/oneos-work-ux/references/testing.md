# 验证：测试人员部署后的真实测试

## 接收与版本
读取正式交接、当前 AC、规则/设计版本、风险与依赖。核部署记录和实际环境的前端、后端及依赖组件；保留 deploymentId、构建/提交与读取证据。预期与实际不同，只对能证明适用的范围出结果，其余阻塞；不能把 A/B-old 的冒烟算作 A/B 的验收。重打包或合并造成 SHA 不同需真实内容等价证据，不机械全量重测、不口头豁免。

第一版通过用户/测试人员发起“已部署，继续验证”恢复，再核实际版本；没有配置事件执行器时，不承诺关掉会话后自动醒来。运行依赖平台进程生命周期，结束前收集结果。

## 用例与方法
从 AC 推导 Given/When/Then，先核是否可测；正常、边界、异常、权限、空态、关联影响按实际风险覆盖。小改动轻测；资金、权限、状态机、跨模块/双端与共享能力扩大回归。SQL/配置缺失、账号或数据不可用是阻塞，不能自动补运行假数据。

- 确定性业务：单元/接口/程序断言检查日期、金额、计数、状态、导出文件和幂等。
- 稳定 UI：Playwright 组织操作和断言，关键接口授权不能只测按钮隐藏。
- 视觉交互：Midscene 帮助找控件、操作、观察提示/遮挡；真实入口及模板见 [midscene.md](midscene.md)。明确预期，操作成功不等于业务成功。
- 设计：按本任务锁定规范核样式、断点、明暗/状态、实际页面；新视觉基准不能由失败截图自动更新成通过基准。
- 专项：性能、安全、移动端原生需相应环境/方法，未执行就明示，不冒称浏览器覆盖全部平台。

## 数据、预算与失败
使用约定 TEST 环境、角色和带运行标识的测试数据；记录创建/清理策略。不得复用他人可变数据导致互相污染。并发影响同一环境时协调执行窗口；测中部署变更按时间段拆证据，不混成同一版本。

一次自动化故障先保存现场，最多一次诊断重试，保留首轮失败；连续失败或预算耗尽标阻塞。AI定位失败、模型超时、环境问题和产品缺陷分开。缓存可复用操作计划，不复用通过结论。不可随意改预期、跳过失败、删除未测项换绿灯。

## 结果与闭环
每条结果含 AC/用例、部署版本、环境、身份/数据、步骤、期望、实际、证据、结论。状态为 passed/failed/blocked/not_run；skipped 不计通过。例外须真实决定、范围和原因，仍可见。

缺陷：查重→归因（需求缺口/规则冲突/实现偏差/集成/回归/测试基础设施）→交回对应职责。未经实际定位，根因写待分析。返修走交付方法，等统一部署后独立复测原失败及关联回归。每个关闭缺陷有自己的证据；不拿一份总绿报告批量关闭。

独立执行：验证者从原规则独立检查，不只读开发的结论。实际执行者/会话要记录；同一实施者自验标 self_check 或 assisted_verification；团队接受自验作为验收依据也不改变执行独立性，只有实际独立执行才能写 independent_qa。工具报告不是 QA 身份证明。

本包结论止于测试结果和交接。`check_packet.py result` 是字段完整性提示，不读远端、不执行测试、不授予关单权限。平台回写按实际授权及官方读回，测试通过不自动关闭整个需求或触发发布。
