# 按需专业方法

只有影响相关判断才加载此页；不产生额外岗位审批。

业务：查规则出处、版本、角色、对象、状态、资格、例外和反向路径。术语不清先找正式定义；当前代码与业务冲突时保留双方，不能自动以代码为准。

产品：从用户目标整理起点→操作→结果，范围、非目标、关键失败、权限、验收 ID。原型只在界面或交互理解需要时做；简单优化不强制长 PRD。

架构：跨服务、公共能力、事务/一致性或新组件时比较最少可行方案，写清依赖、兼容、失败恢复和影响。API/数据库变更必须识别消费者与迁移；不擅自扩大为重构工程。

指标：分子、分母、对象范围、时间窗、去重、排除项和精度；给已知输入/预期样例。取不到数据就保留未知，不用模拟值冒充真实数字。

体验：转本包 design.md 方法；最新已确认业务约束决定动作，规范决定视觉交互；不自造颜色/布局“更好看”。

知识整理：只有稳定、可追溯的净变化入库；候选不自动转正式规则。重复问题补充证据与关联，不新增同义条目。
