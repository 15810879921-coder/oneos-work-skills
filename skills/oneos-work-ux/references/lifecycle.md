# 云端可恢复记录

这些是内部语义，不是硬编码的云效/HiFox状态名：scoped → implementing → branch_ready → awaiting_test_deploy → test_ready → testing → tested；失败进入 rework，返修回 implementing，再等待统一部署。blocked 记录具体原因和受影响范围，不抹掉已完成步骤。

状态变化由真实事实驱动：branch_ready有实际合入和检查；test_ready有匹配部署版本及账号/数据；tested有全范围适用结果与缺陷。测试人员部署是外部事实，收到消息后仍核实。测试通过不自动关闭整需求，也不生成发布动作。

复用原平台任务/交接记录存一个可恢复摘要，模板 templates/run-record.json。每次交接或中断前保存：记录版本、当前阶段、AC和含义版本、双库提交、设计版本、源/目标提交、部署组件、证据引用、缺口、下一动作。使用当前平台官方工具写后读回；本地草稿、outbox和准备好的文本不等于云端成功。

避免覆盖并发结果：写前读当前 revision/更新时间，变化则合并或重新核对；平台支持条件写就使用。重复恢复以 eventId/执行ID去重；状态更新失败只补写，不重复测试或业务操作。环境版本变化开启新执行，旧结果保留。

结果证据不可变追加。check_packet 的 result 输入只放当前适用的有效结果；复测解决失败时要在历史记录显式引用 supersedesResultId 和原因，不能通过删失败来让检查变绿。原未测AC继续可见。

平台读写与仓库动作都需已有授权；不因本包写“持续推进”自动发消息、创建他人任务或唤起Agent。无后台执行器时等待是持久化交接，不是承诺本会话结束后还能运行。
