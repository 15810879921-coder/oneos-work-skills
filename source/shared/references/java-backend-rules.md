# Java 后端开发规则

规则版本 1.1.1。适用于 Java 后端实现、修复、重构、自检和代码审查；验证入口针对本次 Java 后端验收范围读取。纯 UI/UX、非 Java 任务不因此加载本规则或扩大数据库调查。

## 总优先级

正确性、安全和业务约束必须满足，包括鉴权、数据权限、业务唯一性、必要原子性及结果正确性。先满足这些条件，再选最简单且足够的实现。事务、异步、缓存、锁、索引和读写分离按场景选择，数据源支持并发仅是候选条件。下文“按需”“简单”“略过”均不能豁免上述约束。

## 1. 先判断实际场景，再选择方案。

根据需求、目标代码、直接调用链和实际风险，决定是否需要事务、并发、幂等、索引、缓存或读写分离。无关项直接略过，简单实现满足要求就保留。

## 2. 沿用项目已有架构和风格。

先参考目标仓同类实现，遵循现有框架、包结构、命名、异常和返回约定。保护已有改动，不顺手重构无关代码。

## 3. 只生成需要的分层。

根据实际架构使用 Entity、Mapper/Repository、Service、Controller、DTO/VO，不强制全部生成，不固定开发顺序，不新增无作用的接口或转发层。

## 4. 职责与数据边界明确。

协议处理、业务编排和数据访问沿项目边界组织；控制客户端可修改字段，防止越权赋值和敏感字段泄露。对象映射要求语义准确，不要求每层字段完全相同。

## 5. 修改 Java 代码须对应中文行注释。

新增或修改的 Java 代码及对应测试、示例，每个非空代码物理行都要有对应中文行注释，包括 package/import、注解、链式续行及独立大括号。注释解释意图和边界；不得为加注释改变 SQL、字符串或文本块内容，也不扩展到未修改的历史代码。

## 6. 改字段或接口时，检查真实关联链路。

按实际影响核对数据库、Entity、映射、SQL、DTO/VO、校验、接口和消费者。只有确实涉及前端、菜单或权限配置时才检查对应部分，不自动扩大修改范围。

## 7. 接口遵循现有合同，输入有明确边界。

沿用项目路径、返回体、HTTP 状态和错误码；明确字段未传、显式 null、置空及局部更新语义。分页、游标、查询上限、时间跨度和排序白名单按实际需要设置，不固定统一数值。

## 8. SQL 参数安全，查询与索引按证据优化。

数据值使用参数绑定，动态标识符采用固定分支或服务端允许的映射。发现重复查询、N+1、扫描或排序问题时处理相关根因；索引结合实际 SQL、已有索引、执行计划及读写代价选择，不逐列建索引、不设通用数量上限。

## 9. 表结构与迁移表达真实业务语义。

主键、空值、默认值、字段类型和迁移方式跟随项目与业务，不统一强加 id、软删除或默认值。新增列有准确中文描述；涉及历史兼容、大表 DDL 或数据变更时，核对应影响，不能把“脚本有版本号”当作实际结构正确的证明。

## 10. 事务优先保证业务正确性。

根据原子性、隔离级别、代理和调用路径设计事务，不靠注解数量判断生效，不统一强制 public 或逐个添加 rollbackFor。要求同一快照时采用能满足该要求的查询方式；异步不继承父事务，不跨线程共享数据库会话资源。

## 11. 并发写与重复执行按实际风险处理。

涉及库存、余额、状态流转等竞争时，选择原子条件更新、唯一约束、版本号或必要行锁，并核影响行数。存在重试、回调或重复提交时再设计幂等；提交结果不明先核实，不直接重复产生副作用。

## 12. 软删除按业务生命周期设计。

明确有效记录、历史、恢复和永久清理的语义，检查实际查询及关联过滤。唯一性要覆盖删除、重建和恢复场景，不能认为加入布尔 del_flag 就解决了重复创建问题。

## 13. 同步或异步按收益和正确性选择。

单查询、有依赖、要求同一事务快照或资源不足时保持同步，必要时批量或合并 SQL。采用异步后，按实际 JDK 选择实现，限制线程、队列、扇出和下游并发，设置统一超时预算，处理上下文、失败及资源释放。Future 超时或取消不等于 SQL 已停止。

## 14. 异步业务任务必须准确表达状态。

只有业务允许稍后完成时才采用。需要可靠受理就先持久化，再返回“已受理/处理中”；按实际要求处理崩溃恢复、重复消费、失败反馈及补偿，不能提前返回假的完成结果。

## 15. 读写分离与缓存独立决策。

读写分离结合现有副本、实际负载和陈旧容忍决定；关键写后读、库存或余额决策等默认走主库。缓存结合收益和一致性要求决定，处理权限、key、失效失败、旧值回填及实际多实例影响；强一致场景可以绕过缓存。

## 16. 金额和时间类型按语义选择。

金额明确单位、币种、精度、舍入与溢出，采用精确表示。时间区分日期、本地时间和绝对时刻，明确时区、精度及序列化；不把所有时间类型一律替换成 LocalDateTime。纯 Java 运算也适用，但不因此扩展数据库调查。

## 17. 验证与审查跟随实际改动。

使用相关编译、定向测试和行为验证，覆盖适用的正常、异常、边界与权限路径；复用有效同版本证据，变化后只重验受影响部分。普通改动不强制全仓检查或性能压测；未实测不宣称性能最优，未验证不宣称通过。发现问题先定位和最小修复，不默认回滚或覆盖已有工作。
